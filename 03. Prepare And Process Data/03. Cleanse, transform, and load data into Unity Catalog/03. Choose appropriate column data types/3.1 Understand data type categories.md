# Understand data type categories

Azure Databricks organizes data types into categories based on their characteristics and use cases. Understanding these categories helps you narrow down your options when choosing a type for a specific column. Choosing the right data type is one of the most important decisions you make when designing a table schema. The data type determines how values are stored, how much space they consume, what operations are allowed, and how queries perform. A well-chosen type improves storage efficiency, speeds up queries, and prevents errors. A poorly chosen type wastes space, slows down queries, and can cause unexpected results or failures. This section explains each category of data types in detail, provides code examples with comments, and offers guidance on when to use each type.

The categories are numeric types, date-time types, text and binary types, and complex types. Numeric types handle mathematical values and calculations. They include integral types, decimal types, and floating-point types. Date-time types represent temporal data. They include DATE, TIMESTAMP, and TIMESTAMP_NTZ. Text and binary types store character and byte sequences. They include STRING and BINARY. Complex types organize nested or repeated data. They include ARRAY, MAP, and STRUCT. Each category has its own strengths and tradeoffs. By the end of this section, you will understand how to choose the right type for each column in your tables.

## Numeric types

Numeric types handle mathematical values and calculations. They are used for quantities, amounts, counts, measurements, identifiers, and any other value that represents a number. Azure Databricks provides several numeric types. They are divided into three subcategories: integral types, decimal types, and floating-point types. Each subcategory has different precision, range, and storage characteristics.

### Integral types

Integral types represent whole numbers. They do not have a fractional part. They are used for counts, identifiers, ages, quantities, and any other value that is naturally a whole number. The integral types in Azure Databricks are TINYINT, SMALLINT, INT, and BIGINT. They differ in the range of values they can store and the amount of storage they consume.

TINYINT stores 1-byte signed integers. The range is -128 to 127. It is useful for very small numbers, such as a flag value or a small code. SMALLINT stores 2-byte signed integers. The range is -32,768 to 32,767. It is useful for small numbers, such as a year or a small count. INT stores 4-byte signed integers. The range is -2,147,483,648 to 2,147,483,647. It is the most commonly used integral type. It is suitable for most counts and identifiers. BIGINT stores 8-byte signed integers. The range is -9,223,372,036,854,775,808 to 9,223,372,036,854,775,807. It is used for very large numbers, such as a row count in a massive table or a timestamp in milliseconds.

When choosing an integral type, use the smallest type that can comfortably hold all possible values. This saves storage and can improve query performance. However, be careful not to choose a type that is too small. If a value exceeds the range of the type, the write will fail or the value will overflow. For example, if you use TINYINT for a counter that can exceed 127, you will eventually encounter an error. It is better to use INT or BIGINT if you are unsure. The following SQL example creates a table with integral columns. Each line is commented.

```sql
-- Create a table named inventory.
-- The product_id column uses INT, which is suitable for most identifiers.
-- The quantity column uses SMALLINT, which is sufficient for typical inventory counts.
-- The reorder_level column uses TINYINT, which is sufficient for small thresholds.
-- The total_sold column uses BIGINT, which can hold very large counts.
CREATE TABLE inventory (
    product_id INT,
    quantity SMALLINT,
    reorder_level TINYINT,
    total_sold BIGINT
);
```

The following PySpark example creates a DataFrame with the same schema and writes it to a table. Each line is commented.

```python
# Import the required types.
from pyspark.sql.types import StructType, StructField, IntegerType, ShortType, ByteType, LongType

# Define the schema.
# IntegerType corresponds to INT.
# ShortType corresponds to SMALLINT.
# ByteType corresponds to TINYINT.
# LongType corresponds to BIGINT.
schema = StructType([
    StructField("product_id", IntegerType(), True),
    StructField("quantity", ShortType(), True),
    StructField("reorder_level", ByteType(), True),
    StructField("total_sold", LongType(), True)
])

# Create a DataFrame with sample data.
data = [(1, 100, 10, 5000), (2, 50, 5, 10000)]

# Create the DataFrame.
df = spark.createDataFrame(data, schema)

# Write the DataFrame to a table.
df.write.saveAsTable("inventory")
```

### Decimal types

Decimal types represent exact numeric values with a fixed precision and scale. They are used for financial data, monetary amounts, and any value where exact precision is required. The decimal type in Azure Databricks is DECIMAL(p,s). The p is the precision, which is the total number of digits. The s is the scale, which is the number of digits to the right of the decimal point. For example, DECIMAL(10,2) can store values with up to 10 total digits, 2 of which are after the decimal point. The maximum value is 99,999,999.99. The minimum value is -99,999,999.99.

Decimal types are exact. They do not suffer from rounding errors like floating-point types. This makes them suitable for money. For example, if you store 0.1 and 0.2 as floating-point numbers and add them, you may get 0.30000000000000004. If you store them as decimals, you get exactly 0.3. This is critical for financial calculations. Decimal types are also used for any value where you need to control the number of decimal places, such as tax rates, percentages, and measurements.

When choosing a decimal type, choose a precision and scale that match your data. If you choose a precision that is too small, you will not be able to store large values. If you choose a scale that is too small, you will lose precision. If you choose a precision and scale that are too large, you will waste storage. For financial data, DECIMAL(18,2) or DECIMAL(38,2) is common. DECIMAL(38,2) can store values up to 99,999,999,999,999,999,999,999,999,999,999,999.99. This is more than enough for most financial applications. The following SQL example creates a table with decimal columns. Each line is commented.

```sql
-- Create a table named financial_transactions.
-- The amount column uses DECIMAL(18,2).
-- This allows values up to 9,999,999,999,999,999.99.
-- The tax_rate column uses DECIMAL(5,4).
-- This allows values up to 9.9999, which is sufficient for tax rates.
CREATE TABLE financial_transactions (
    transaction_id INT,
    amount DECIMAL(18,2),
    tax_rate DECIMAL(5,4)
);
```

The following PySpark example creates a DataFrame with decimal columns. Each line is commented.

```python
from pyspark.sql.types import StructType, StructField, IntegerType, DecimalType
from decimal import Decimal

# Define the schema.
# DecimalType(18,2) corresponds to DECIMAL(18,2).
# DecimalType(5,4) corresponds to DECIMAL(5,4).
schema = StructType([
    StructField("transaction_id", IntegerType(), True),
    StructField("amount", DecimalType(18,2), True),
    StructField("tax_rate", DecimalType(5,4), True)
])

# Create a DataFrame with sample data.
data = [(1, Decimal("12345.67"), Decimal("0.0825"))]

# Create the DataFrame.
df = spark.createDataFrame(data, schema)

# Write the DataFrame to a table.
df.write.saveAsTable("financial_transactions")
```

### Floating-point types

Floating-point types represent approximate numeric values. They are used for scientific calculations, measurements, and any value where a small amount of imprecision is acceptable. The floating-point types in Azure Databricks are FLOAT and DOUBLE. FLOAT is a 4-byte single-precision floating-point number. DOUBLE is an 8-byte double-precision floating-point number. DOUBLE has more precision than FLOAT. It is the default for floating-point literals in many systems.

Floating-point types are not exact. They store values in a binary format that cannot represent all decimal fractions exactly. For example, 0.1 cannot be represented exactly as a floating-point number. This can lead to small rounding errors. For most scientific and engineering applications, these errors are acceptable. For financial applications, they are not. You should use decimal types for financial data.

When choosing between FLOAT and DOUBLE, use DOUBLE if you need more precision. Use FLOAT if you need to save storage and you can tolerate less precision. In most cases, DOUBLE is the safer choice. The following SQL example creates a table with floating-point columns. Each line is commented.

```sql
-- Create a table named sensor_readings.
-- The temperature column uses DOUBLE, which provides good precision.
-- The humidity column uses FLOAT, which saves storage and is sufficient for humidity.
CREATE TABLE sensor_readings (
    sensor_id INT,
    temperature DOUBLE,
    humidity FLOAT
);
```

The following PySpark example creates a DataFrame with floating-point columns. Each line is commented.

```python
from pyspark.sql.types import StructType, StructField, IntegerType, DoubleType, FloatType

# Define the schema.
# DoubleType corresponds to DOUBLE.
# FloatType corresponds to FLOAT.
schema = StructType([
    StructField("sensor_id", IntegerType(), True),
    StructField("temperature", DoubleType(), True),
    StructField("humidity", FloatType(), True)
])

# Create a DataFrame with sample data.
data = [(1, 23.5, 45.2), (2, 24.1, 46.8)]

# Create the DataFrame.
df = spark.createDataFrame(data, schema)

# Write the DataFrame to a table.
df.write.saveAsTable("sensor_readings")
```

## Date-time types

Date-time types represent temporal data. They are used for dates, times, timestamps, and durations. Azure Databricks provides three date-time types: DATE, TIMESTAMP, and TIMESTAMP_NTZ. Each has a different purpose and behavior.

### DATE

DATE represents a calendar date without a time component. It stores year, month, and day. It does not store hours, minutes, seconds, or time zone. DATE is used for birthdays, hire dates, transaction dates, and any other value that is a date without a time. The range of DATE is from 0001-01-01 to 9999-12-31. The following SQL example creates a table with a DATE column. Each line is commented.

```sql
-- Create a table named employees.
-- The hire_date column uses DATE.
-- It stores only the date, not the time.
CREATE TABLE employees (
    employee_id INT,
    name STRING,
    hire_date DATE
);
```

The following PySpark example creates a DataFrame with a DATE column. Each line is commented.

```python
from pyspark.sql.types import StructType, StructField, IntegerType, StringType, DateType
from datetime import date

# Define the schema.
# DateType corresponds to DATE.
schema = StructType([
    StructField("employee_id", IntegerType(), True),
    StructField("name", StringType(), True),
    StructField("hire_date", DateType(), True)
])

# Create a DataFrame with sample data.
data = [(1, "Alice", date(2020, 1, 15)), (2, "Bob", date(2021, 3, 10))]

# Create the DataFrame.
df = spark.createDataFrame(data, schema)

# Write the DataFrame to a table.
df.write.saveAsTable("employees")
```

### TIMESTAMP

TIMESTAMP represents a date and time with a session time zone. It stores year, month, day, hour, minute, second, and fractional seconds. It also stores the time zone information. The time zone is the session time zone, which is typically UTC in Databricks. When you query a TIMESTAMP column, the value is displayed in the session time zone. When you write a TIMESTAMP value, it is converted from the session time zone to UTC for storage. TIMESTAMP is used for event times, log times, and any value that includes both date and time. The following SQL example creates a table with a TIMESTAMP column. Each line is commented.

```sql
-- Create a table named events.
-- The event_time column uses TIMESTAMP.
-- It stores both date and time, with time zone conversion.
CREATE TABLE events (
    event_id INT,
    event_name STRING,
    event_time TIMESTAMP
);
```

The following PySpark example creates a DataFrame with a TIMESTAMP column. Each line is commented.

```python
from pyspark.sql.types import StructType, StructField, IntegerType, StringType, TimestampType
from datetime import datetime

# Define the schema.
# TimestampType corresponds to TIMESTAMP.
schema = StructType([
    StructField("event_id", IntegerType(), True),
    StructField("event_name", StringType(), True),
    StructField("event_time", TimestampType(), True)
])

# Create a DataFrame with sample data.
data = [(1, "login", datetime(2026, 1, 15, 10, 30, 0)), (2, "logout", datetime(2026, 1, 15, 11, 45, 0))]

# Create the DataFrame.
df = spark.createDataFrame(data, schema)

# Write the DataFrame to a table.
df.write.saveAsTable("events")
```

### TIMESTAMP_NTZ

TIMESTAMP_NTZ represents a date and time without time zone. The NTZ stands for "no time zone". It stores year, month, day, hour, minute, second, and fractional seconds. It does not store time zone information. It does not perform any time zone conversion. The value is stored exactly as given. TIMESTAMP_NTZ is used when you want to store a local date and time without any time zone context. For example, a scheduled appointment time in a local time zone, or a business hours timestamp. It is also used when you want to avoid the complexity of time zone conversion. The following SQL example creates a table with a TIMESTAMP_NTZ column. Each line is commented.

```sql
-- Create a table named appointments.
-- The appointment_time column uses TIMESTAMP_NTZ.
-- It stores the local date and time without time zone conversion.
CREATE TABLE appointments (
    appointment_id INT,
    customer_name STRING,
    appointment_time TIMESTAMP_NTZ
);
```

```python
# Write the DataFrame to a table.
df.write.saveAsTable("appointments")
```

## Text and binary types

Text and binary types store character and byte sequences. They are used for names, descriptions, codes, documents, images, and any other value that is not numeric or temporal. Azure Databricks provides STRING and BINARY.

### STRING

STRING stores variable-length text. It can hold any sequence of characters, including letters, numbers, symbols, and whitespace. STRING is the most commonly used type for text data. It has a maximum length of 2 gigabytes. STRING is used for names, addresses, emails, phone numbers, comments, JSON documents, XML documents, and any other textual data. The following SQL example creates a table with STRING columns. Each line is commented.

```sql
-- Create a table named customers.
-- The name, email, and phone_number columns use STRING.
-- STRING stores variable-length text.
CREATE TABLE customers (
    customer_id INT,
    name STRING,
    email STRING,
    phone_number STRING
);
```

The following PySpark example creates a DataFrame with STRING columns. Each line is commented.

```python
from pyspark.sql.types import StructType, StructField, IntegerType, StringType

# Define the schema.
# StringType corresponds to STRING.
schema = StructType([
    StructField("customer_id", IntegerType(), True),
    StructField("name", StringType(), True),
    StructField("email", StringType(), True),
    StructField("phone_number", StringType(), True)
])

# Create a DataFrame with sample data.
data = [(1, "Alice", "alice@example.com", "555-1234"), (2, "Bob", "bob@example.com", "555-5678")]

# Create the DataFrame.
df = spark.createDataFrame(data, schema)

# Write the DataFrame to a table.
df.write.saveAsTable("customers")
```

### BINARY

BINARY stores raw byte sequences. It is used for binary data such as images, audio, video, and serialized objects. BINARY is not human-readable. It is stored as a sequence of bytes. BINARY is useful when you need to store data that is not text, such as a hash, an encrypted value, or a compressed file. The following SQL example creates a table with a BINARY column. Each line is commented.

```sql
-- Create a table named documents.
-- The content column uses BINARY.
-- It stores raw bytes.
CREATE TABLE documents (
    document_id INT,
    file_name STRING,
    content BINARY
);
```

## Complex types

Complex types organize nested or repeated data. They allow you to store arrays, maps, and structs within a single column. Complex types are used for semi-structured data, JSON data, and hierarchical data. They are powerful but can be more difficult to query and manage than simple types. Azure Databricks provides ARRAY, MAP, and STRUCT.

### ARRAY

ARRAY stores an ordered sequence of elements. All elements must have the same type. For example, an array of integers, an array of strings, or an array of structs. ARRAY is used for lists, tags, phone numbers, and any other collection of values. The following SQL example creates a table with an ARRAY column. Each line is commented.

```sql
-- Create a table named products.
-- The tags column uses ARRAY<STRING>.
-- It stores an array of strings.
CREATE TABLE products (
    product_id INT,
    name STRING,
    tags ARRAY<STRING>
);
```

The following PySpark example creates a DataFrame with an ARRAY column. Each line is commented.

```python
from pyspark.sql.types import StructType, StructField, IntegerType, StringType, ArrayType

# Define the schema.
# ArrayType(StringType(), True) corresponds to ARRAY<STRING>.
schema = StructType([
    StructField("product_id", IntegerType(), True),
    StructField("name", StringType(), True),
    StructField("tags", ArrayType(StringType(), True), True)
])

# Create a DataFrame with sample data.
data = [(1, "Laptop", ["electronics", "computers"]), (2, "Shirt", ["clothing", "men"])]

# Create the DataFrame.
df = spark.createDataFrame(data, schema)

# Write the DataFrame to a table.
df.write.saveAsTable("products")
```

### MAP

MAP stores key-value pairs. All keys must have the same type. All values must have the same type. MAP is used for dictionaries, attributes, and any other associative collection. The following SQL example creates a table with a MAP column. Each line is commented.

```sql
-- Create a table named user_settings.
-- The settings column uses MAP<STRING, STRING>.
-- It stores key-value pairs where both keys and values are strings.
CREATE TABLE user_settings (
    user_id INT,
    settings MAP<STRING, STRING>
);
```

The following PySpark example creates a DataFrame with a MAP column. Each line is commented.

```python
from pyspark.sql.types import StructType, StructField, IntegerType, StringType, MapType

# Define the schema.
# MapType(StringType(), StringType(), True) corresponds to MAP<STRING, STRING>.
schema = StructType([
    StructField("user_id", IntegerType(), True),
    StructField("settings", MapType(StringType(), StringType(), True), True)
])

# Create a DataFrame with sample data.
data = [(1, {"theme": "dark", "language": "en"}), (2, {"theme": "light", "language": "fr"})]

# Create the DataFrame.
df = spark.createDataFrame(data, schema)

# Write the DataFrame to a table.
df.write.saveAsTable("user_settings")
```

### STRUCT

STRUCT stores a record with named fields. Each field has a name and a type. STRUCT is used for nested records, such as an address with street, city, state, and zip. The following SQL example creates a table with a STRUCT column. Each line is commented.

```sql
-- Create a table named customers_with_address.
-- The address column uses STRUCT<street:STRING, city:STRING, state:STRING, zip:STRING>.
-- It stores a nested record.
CREATE TABLE customers_with_address (
    customer_id INT,
    name STRING,
    address STRUCT<street:STRING, city:STRING, state:STRING, zip:STRING>
);
```

The following PySpark example creates a DataFrame with a STRUCT column. Each line is commented.

```python
from pyspark.sql.types import StructType, StructField, IntegerType, StringType

# Define the schema for the address struct.
address_schema = StructType([
    StructField("street", StringType(), True),
    StructField("city", StringType(), True),
    StructField("state", StringType(), True),
    StructField("zip", StringType(), True)
])

# Define the schema for the table.
schema = StructType([
    StructField("customer_id", IntegerType(), True),
    StructField("name", StringType(), True),
    StructField("address", address_schema, True)
])

# Create a DataFrame with sample data.
data = [(1, "Alice", ("123 Main St", "Springfield", "IL", "62701")),
        (2, "Bob", ("456 Oak Ave", "Portland", "OR", "97201"))]

# Create the DataFrame.
df = spark.createDataFrame(data, schema)

# Write the DataFrame to a table.
df.write.saveAsTable("customers_with_address")
```

## Choosing the right type

Choosing the right type for each column is a balance between storage efficiency, query performance, and correctness. Consider the following guidelines. Use the smallest numeric type that can hold all possible values. Use DECIMAL for exact values such as money. Use DOUBLE for approximate values such as scientific measurements. Use DATE for dates without times. Use TIMESTAMP for date and time with time zone. Use TIMESTAMP_NTZ for local date and time without time zone. Use STRING for text. Use BINARY for raw bytes. Use ARRAY, MAP, and STRUCT for nested and repeated data. Avoid using STRING for numeric or date values. Avoid using FLOAT or DOUBLE for money. Avoid using overly large types such as BIGINT when INT is sufficient. Test your schema with sample data to ensure that the types are correct and that the data fits.

They include DATE, TIMESTAMP, and TIMESTAMP_NTZ. Text and binary types store character and byte sequences. They include STRING and BINARY. Complex types organize nested or repeated data. They include ARRAY, MAP, and STRUCT. By choosing the right type for each column, you improve storage efficiency, query performance, and data correctness. You also make your schema easier to understand and maintain. Use the guidelines in this section to choose types wisely. Test your choices with sample data. Document your choices. Review your schema regularly as your data and requirements evolve.
