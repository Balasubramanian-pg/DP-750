## Data Source Connection Considerations

The architecture of your ingestion pipeline begins not with code, but with connectivity. How Azure Databricks establishes trust and communicates with source systems dictates the security posture, reliability, and performance of your entire data platform. A well-designed connection strategy minimizes latency, protects credentials, and ensures that extraction does not destabilize critical source systems.

### Cloud Object Storage Sources

Cloud storage platforms like Azure Data Lake Storage Gen2 (ADLS), Amazon S3, and Google Cloud Storage are the primary landing zones for modern data lakes. Connecting to them requires more than just a URL; it demands a governed approach to access and organization.

#### Governance via Unity Catalog
Instead of managing individual storage keys or SAS tokens in notebooks, use **Unity Catalog External Locations**. This abstraction layer allows you to define storage paths and associate them with specific storage credentials (such as Managed Identities or Service Principals). Users then access data through Unity Catalog permissions, decoupling infrastructure security from data access logic.

#### Strategic Folder Structures
The physical organization of files in cloud storage directly impacts ingestion efficiency. A chaotic folder structure forces the engine to list thousands of irrelevant files, creating significant overhead.

*   **Hive-Style Partitioning:** Organize files using `key=value` directories (e.g., `/sales/year=2025/month=11/`). This allows Azure Databricks to perform **partition pruning**, skipping entire directories during reads and automatically extracting partition values as columns without parsing file contents.
*   **Source Segregation:** Keep data from different systems isolated (e.g., `/landing/erp/`, `/landing/crm/`). This simplifies processing logic and prevents schema conflicts between unrelated datasets.
*   **State Management:** For file-based workflows, consider a state-aware structure:
    *   `/incoming/`: Where new files land.
    *   `/processing/`: Files currently being read.
    *   `/archive/`: Successfully ingested files.
    *   `/failed/`: Files that triggered errors.

> [!TIP]
> **Auto Loader Optimization**
> Azure Databricks **Auto Loader** is designed to efficiently discover new files in cloud storage. It uses a checkpointing mechanism to track which files have been processed. Structuring your folders to align with Auto Loader’s discovery patterns—avoiding deeply nested, flat hierarchies with millions of files—ensures near-real-time ingestion with minimal overhead.

### Database Sources

Connecting to transactional databases (SQL Server, PostgreSQL, Oracle) requires balancing data freshness with source system stability.

*   **Network Security:** Ensure secure connectivity via Private Link or VNet injection to keep traffic off the public internet.
*   **Credential Management:** Never hardcode passwords. Use **Databricks Secrets** backed by Azure Key Vault to inject credentials at runtime.
*   **Performance Protection:** Use **query pushdown** to filter and aggregate data at the source before it enters Databricks. Implement connection pooling to avoid exhausting database connection limits during high-concurrency extractions.
*   **Impact Monitoring:** Monitor the source database’s CPU and I/O during extraction windows. If ingestion causes latency for operational users, switch from direct queries to Change Data Capture (CDC) or log-based replication.

### Streaming Sources

Message buses like Azure Event Hubs, Kafka, or Kinesis provide continuous, real-time data streams. Connecting to these sources requires a shift from batch-oriented thinking to event-driven architecture.

*   **Consumer Groups:** Configure unique consumer groups for each Databricks streaming job. This allows multiple applications to read the same stream independently without interfering with each other’s offset tracking.
*   **Offset Management:** Databricks manages offsets automatically via checkpoints, ensuring exactly-once or at-least-once semantics even in the event of failures.
*   **Schema Registry:** Integrate with a Schema Registry (such as Confluent or Azure Schema Registry) to validate message formats. This prevents pipeline failures when upstream producers change their data structure.

### SaaS Application Sources

Enterprise applications like Salesforce, ServiceNow, and SAP expose data through APIs, which introduce unique constraints compared to databases or files.

*   **Rate Limiting:** APIs often enforce strict throttling. Design your ingestion to respect these limits by implementing exponential backoff and retry logic.
*   **Pagination:** Large datasets must be retrieved in chunks. Your pipeline must handle pagination tokens or cursor-based navigation to ensure complete data capture.
*   **Authentication Flows:** Modern SaaS apps use OAuth 2.0 or certificate-based authentication. Securely manage token refresh cycles using Databricks Secrets to prevent session expirations during long-running jobs.
*   **Change Tracking:** Leverage native API features like webhooks or "last modified" filters to perform incremental extractions, reducing the load on both the API and your pipeline.

By carefully configuring these connections, you create a robust ingress layer that is secure, efficient, and resilient to the diverse challenges posed by modern data sources.
