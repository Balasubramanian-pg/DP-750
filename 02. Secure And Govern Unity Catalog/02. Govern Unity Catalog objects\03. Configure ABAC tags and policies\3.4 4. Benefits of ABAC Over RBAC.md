## 4. Benefits of ABAC Over RBAC

| Feature | Role-Based Access Control (RBAC) | Attribute-Based Access Control (ABAC) |
| :--- | :--- | :--- |
| **Scalability** | Low. Requires manual grants for each new table/user. | High. Policies automatically apply to new assets based on tags. |
| **Granularity** | Coarse. Typically at the table or schema level. | Fine. Can be applied at the column or row level. |
| **Maintenance** | High. Constant updates needed as teams and data change. | Low. Once policies are set, they self-enforce. |
| **Context Awareness** | None. Access is static. | Dynamic. Access can depend on time, location, or user attributes. |
| **Error Proneness** | High. Easy to forget a grant or revoke. | Low. Logic is centralized in policies. |
