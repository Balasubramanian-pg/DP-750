## Organize with Tags

While comments provide free-form descriptive text, **tags** offer structured classification. Tags are key-value pairs that allow you to categorize assets for search, automation, and policy enforcement. They transform metadata from a passive description into an active governance tool.

### Adding Tags via SQL

You can apply tags to tables, views, and individual columns using the `ALTER TABLE ... SET TAGS` syntax. This allows for granular classification, such as marking specific columns as containing PII or identifying tables belonging to a specific business domain.

```sql
-- Add multiple tags to a table
ALTER TABLE sales.customers.profiles 
SET TAGS (
    'domain' = 'sales', 
    'data_classification' = 'internal'
);

-- Add tags to a specific column for fine-grained governance
ALTER TABLE sales.customers.profiles 
ALTER COLUMN email 
SET TAGS (
    'pii' = 'email', 
    'sensitivity' = 'high'
);
```

### Removing Tags

If a classification is no longer accurate, you can remove specific tags using the `UNSET TAGS` command. Note that you only need to specify the key of the tag you wish to remove.

```sql
-- Remove the 'domain' tag from the table
ALTER TABLE sales.customers.profiles 
UNSET TAGS ('domain');
```

### Strategic Use of Tags

*   **Automated Policy Enforcement:** Tags like `sensitivity = 'high'` can be used in Attribute-Based Access Control (ABAC) policies to automatically restrict access to sensitive data.
*   **Cost Allocation:** Tags such as `cost_center = 'engineering'` help finance teams track storage and compute costs associated with specific datasets.
*   **Discovery and Search:** Users can filter the Catalog Explorer by tag values, making it easier to find all tables related to a specific project or compliance requirement.

> [!IMPORTANT]
> **Governed Tags**
> For tags to be used in ABAC policies, they must be defined as **Governed Tags** at the metastore level. This ensures that tag keys and values are standardized across the organization, preventing inconsistencies like `sensitivity: high` vs. `sensitivity: High`.
