# Preserve table and column definitions

Description: Learn how to create, implement, and preserve table and column definitions and descriptions for data discovery in Unity Catalog using comments, tags, and exploration tools.

## Preserve Table and Column Definitions

Well-documented metadata is the bedrock of effective data governance. Without it, even the most meticulously organized catalog becomes a labyrinth of indecipherable identifiers. Comprehensive comments and tags transform raw schema definitions into a self-documenting knowledge base, enabling data consumers to discover, understand, and trust the assets they rely on. This is particularly critical in an era where AI-driven discovery tools depend entirely on high-quality metadata to surface relevant insights.

### The Power of Inline Comments

Comments provide human-readable context that technical names alone cannot convey. In Unity Catalog, you can attach comments to any securable object—catalogs, schemas, tables, views, and individual columns. The most effective place to embed this context is directly within the Data Definition Language (DDL) at the time of creation.

Consider the difference between a bare schema and one enriched with purpose:

```sql
CREATE TABLE sales.customers.profiles (
    customer_id BIGINT COMMENT 'Unique identifier for each customer',
    email STRING COMMENT 'Customer primary email address',
    created_date DATE COMMENT 'Date when customer account was created',
    preferences STRUCT<notifications: BOOLEAN, language: STRING> COMMENT 'Customer preference settings'
);
```

By defining comments inline, you ensure that the documentation travels with the object. If the table is cloned, migrated, or viewed in a different workspace, the context remains intact. This practice prevents the "documentation drift" that occurs when descriptions are stored in external wikis or spreadsheets that rarely stay in sync with the actual data.

### Enhancing Complex Types

Comments are especially valuable for complex data types like `STRUCT`, `ARRAY`, or `MAP`. A column named `preferences` might be ambiguous on its own, but the comment `'Customer preference settings'` immediately clarifies its intent. For nested fields, you can further document the structure by adding comments to the inner elements if your DDL syntax supports it, or by providing a comprehensive description at the parent level.

> [!NOTE]
> **AI and Discovery**
> AI/BI Genie and other semantic search tools use these comments to match natural language queries to database columns. A user asking for "customer contact info" is far more likely to find the `email` column if it is explicitly described as `'Customer primary email address'` rather than leaving the AI to guess based on the name alone.

### Best Practices for Metadata Preservation

1.  **Be Descriptive, Not Redundant:** Avoid repeating the column name in the comment. Instead of `'The customer ID'`, use `'Unique identifier for each customer'`. Explain *what* the data represents, not just what it is called.
2.  **Document Business Logic:** For calculated columns or flags, explain the logic. For example, `is_active BOOLEAN COMMENT 'True if the customer has placed an order in the last 90 days'`.
3.  **Standardize Terminology:** Use consistent language across your organization. If one team uses "Client" and another uses "Customer," standardizing the comments helps bridge the gap during cross-domain analysis.
4.  **Update with Schema Changes:** When you alter a table to add or modify columns, update the comments simultaneously. Treat metadata changes with the same rigor as code changes.

By embedding rich, accurate comments into your Unity Catalog objects, you create a data environment that is not only governed but also genuinely usable. This foundational step ensures that as your platform scales, the knowledge required to interpret your data scales with it.

## Add Comments Using SQL

While inline comments are ideal during table creation, data assets evolve. You will frequently need to add or refine documentation for existing objects without rebuilding them. Unity Catalog provides robust SQL commands to manage this metadata dynamically, ensuring your documentation remains current as business logic changes.

### Updating Object and Column Metadata

The `COMMENT ON` statement is the primary tool for adding or updating descriptions for tables, views, schemas, and catalogs. For columns, you use the `ALTER COLUMN` syntax within an `ALTER TABLE` statement.

```sql
-- Add or update a comment for an entire table
COMMENT ON TABLE sales.customers.profiles 
IS 'Contains customer profile information including contact details and preferences';

-- Add or update a comment for a specific column
ALTER TABLE sales.customers.profiles 
ALTER COLUMN email 
COMMENT 'Primary email address used for account notifications';
```

> [!NOTE]
> **Overwriting Behavior**
> Using these commands will overwrite any existing comment. If you need to preserve previous documentation, ensure you include it in your new string or maintain a version history in your external documentation system.

### Leveraging Markdown for Rich Documentation

Unity Catalog supports **Markdown formatting** within comment strings. This allows you to transform simple text fields into structured, readable documentation that renders beautifully in the Catalog Explorer UI and AI/BI Genie interfaces.

By using headers, bold text, and lists, you can create self-contained documentation blocks that explain complex table structures at a glance.

```sql
COMMENT ON TABLE sales.orders.transactions 
IS '## Order Transactions 
Contains all customer orders with the following key fields: 
- **order_id**: Unique order identifier 
- **customer_id**: Foreign key to customers table 
- **order_date**: Date order was placed';
```

### Why Structured Comments Matter

1.  **Improved Discoverability:** When users browse the catalog, rich text descriptions help them quickly determine if a table contains the data they need without opening it.
2.  **AI Context:** AI/BI Genie uses these descriptions to understand the semantic meaning of tables. A well-structured comment helps the AI distinguish between similar tables (e.g., `orders` vs. `order_items`) by clearly listing their primary keys and purposes.
3.  **Onboarding Efficiency:** New team members can rely on these comments to understand the data model without needing to query senior engineers or search through outdated wikis.

> [!TIP]
> **Standardize Your Templates**
> Create a standard Markdown template for your team’s table comments. For example, always include a "## Purpose" section, a "## Key Fields" list, and a "## Refresh Schedule" note. Consistency makes your catalog feel like a cohesive product rather than a collection of disparate files.


### Required permissions for comments
To add or edit comments, you need:
- Ownership of the object, or
- MODIFY and SELECT privileges on the table
- USE CATALOG and USE SCHEMA on the parent catalog and schema


Tags are key-value pairs that help you organize and categorize data assets in Unity Catalog. Unlike comments, which provide descriptive text, tags enable structured classification and improve search functionality.

### Add tags using SQL
Use the ALTER command with SET TAGS to apply tags:

```
ALTER
```


```
SET TAGS
```


```
-- Add tags to a table ALTER TABLE sales.customers.profiles SET TAGS ('domain' = 'sales', 'data_classification' = 'internal'); -- Add tags to a specific column ALTER TABLE sales.customers.profiles ALTER COLUMN email SET TAGS ('pii' = 'email', 'sensitivity' = 'high');
```


```
-- Add tags to a table ALTER TABLE sales.customers.profiles SET TAGS ('domain' = 'sales', 'data_classification' = 'internal'); -- Add tags to a specific column ALTER TABLE sales.customers.profiles ALTER COLUMN email SET TAGS ('pii' = 'email', 'sensitivity' = 'high');
```

To remove tags, use UNSET TAGS:

```
UNSET TAGS
```


```
ALTER TABLE sales.customers.profiles UNSET TAGS ('domain');
```


```
ALTER TABLE sales.customers.profiles UNSET TAGS ('domain');
```

### Use governed tags
Governed tags provide centralized control over tag definitions. With governed tags, administrators define allowed keys and values at the account level, ensuring consistent classification across the organization. Governed tags appear with a lock icon in Catalog Explorer.
System tags are a special type of governed tag predefined by Azure Databricks for common use cases like data classification, ownership tracking, and lifecycle management.

### Tag constraints
Keep these constraints in mind when working with tags:
- Maximum 50 tags per securable object
- Maximum 1,000 column tags per table
- Tag keys have a 255-character limit
- Tag values have a 1,000-character limit
- Tag keys are case-sensitive

After you create and document your data assets, you need ways to find and explore them. Unity Catalog provides several tools for data discovery.

### Use Catalog Explorer
Catalog Explorer provides a visual interface for navigating your data assets. When you select a table, you can:
- View the Columns tab to see column names, data types, and comments
- Select the Sample Data tab to preview table contents
- Check the Details tab for table properties and metadata
- Review the History tab for Delta table version history
The Insights tab shows frequent queries and users who accessed the table in the past 30 days, helping you understand how data is being used.

### Explore objects using SQL
Use SQL commands to programmatically explore your catalog:

```
-- List all catalogs available to you SHOW CATALOGS; -- List schemas in a catalog SHOW SCHEMAS IN sales; -- List tables in a schema SHOW TABLES IN sales.customers; -- View table details including comments DESCRIBE TABLE EXTENDED sales.customers.profiles; -- View table columns SHOW COLUMNS IN sales.customers.profiles; -- View table properties SHOW TBLPROPERTIES sales.customers.profiles;
```


```
-- List all catalogs available to you SHOW CATALOGS; -- List schemas in a catalog SHOW SCHEMAS IN sales; -- List tables in a schema SHOW TABLES IN sales.customers; -- View table details including comments DESCRIBE TABLE EXTENDED sales.customers.profiles; -- View table columns SHOW COLUMNS IN sales.customers.profiles; -- View table properties SHOW TBLPROPERTIES sales.customers.profiles;
```

You can filter results using pattern matching:

```
-- Find tables matching a pattern SHOW TABLES IN sales.customers LIKE 'profiles_*';
```


```
-- Find tables matching a pattern SHOW TABLES IN sales.customers LIKE 'profiles_*';
```

### Search using tags
Use the workspace search bar to find tables and views by their tags. Enter tag keys or values to locate matching objects. Only objects you have at least the BROWSE privilege on appear in search results.

```
BROWSE
```

### View table relationships
For tables with defined foreign keys, select View relationships in Catalog Explorer to display an Entity Relationship Diagram (ERD). This diagram visualizes how tables connect through primary and foreign key relationships.

### Integrate with AI/BI tools
AI-powered discovery tools like AI/BI Genie use your table comments and tags to provide natural language search and question answering. High-quality metadata directly improves the accuracy of AI-assisted data exploration.
Maintaining comprehensive table and column definitions is an ongoing responsibility. As your data evolves, update your comments and tags to keep them accurate. This investment in metadata quality pays dividends through improved discoverability, governance compliance, and AI-readiness.
