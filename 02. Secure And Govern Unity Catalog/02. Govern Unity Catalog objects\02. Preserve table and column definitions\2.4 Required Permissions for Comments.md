## Required Permissions for Comments

Metadata management in Unity Catalog is governed by a strict permission model to ensure that only authorized personnel can alter the documented definition of data assets. To add or edit comments, you must satisfy a combination of object-level and parent-level privileges.

### Permission Requirements

| Privilege | Scope | Purpose |
| :--- | :--- | :--- |
| **Ownership** | The specific object (Table/View) | Grants full control, including metadata modification. |
| **MODIFY** | The specific object (Table/View) | Allows structural and metadata changes without full ownership. |
| **SELECT** | The specific object (Table/View) | Required alongside `MODIFY` to ensure the user has read access to the data they are documenting. |
| **USE CATALOG** | Parent Catalog | Allows navigation to the catalog level. |
| **USE SCHEMA** | Parent Schema | Allows navigation to the schema level where the object resides. |

> [!NOTE]
> **Viewing Comments**
> Once comments are added, they are visible to any user with the **BROWSE** privilege on the object. This ensures that documentation is widely accessible to data consumers while remaining protected from unauthorized editing.
