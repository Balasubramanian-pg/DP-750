## Workspace Storage

The location and management of workspace storage depend on the type of workspace you deploy. Understanding these distinctions is critical for implementing appropriate security controls and data governance strategies.

### Storage by Workspace Type

*   **Classic (Hybrid) Workspaces:** Utilize a dedicated storage account that resides directly within your Azure subscription. This provides full visibility and control over the underlying infrastructure.
*   **Serverless Workspaces:** Use **default storage**, a fully managed location within the Azure Databricks account infrastructure. This eliminates the need to configure or manage storage accounts in your own subscription.

### Categories of Workspace Data

Regardless of the workspace type, storage is organized into two primary categories:

| Category | Description | Examples |
| :--- | :--- | :--- |
| **Workspace File System** | Assets created and managed by users through the UI. | Notebooks, SQL queries, dashboards, alerts, repos, libraries, and configuration files (Python/YAML). |
| **Workspace System Data** | Data generated internally by Azure Databricks features for observability and operation. | SQL query results, job run outputs, notebook revisions, query plans, and cluster logs. |

### Classic Workspace Storage Details

In classic workspaces, both file system and system data reside in the workspace storage account within your subscription. If Unity Catalog is enabled, this account also hosts the **default workspace catalog**.

*   **Governed Access:** While the data physically resides in your storage account, users interact with it exclusively through the Unity Catalog governance layer. They do not have direct access to the underlying storage, ensuring consistent security and access control.
*   **Legacy DBFS:** The storage account may contain the **Databricks File System (DBFS)**, accessible via the `dbfs:/` namespace. 

> [!WARNING]
> **DBFS Root and Mounts are Deprecated**
> Storing or accessing data via DBFS root or DBFS mounts is a legacy pattern. For improved governance, security, and performance, you should migrate to **Unity Catalog-managed tables and volumes**.

### Security Considerations

Knowing where your data resides allows you to apply precise security measures. For classic workspaces, you can enable firewall support on the workspace storage account to restrict access to only authorized networks and resources, adding an extra layer of protection to your data lakehouse foundation.
