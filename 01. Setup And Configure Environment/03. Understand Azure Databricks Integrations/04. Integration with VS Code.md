# Integration with VS Code

## Local Development with Visual Studio Code

Data engineers often face a fragmented workflow when developing for Azure Databricks, frequently switching between local editors and remote web-based notebooks. This back-and-forth process—copying code, uploading files, and managing context switches—slows development velocity and complicates debugging. The **Databricks extension for Visual Studio Code (VS Code)** resolves these inefficiencies by bridging the gap between local development and remote execution.

### Seamless Integration

The extension connects your local VS Code environment directly to your Azure Databricks workspace, allowing you to leverage familiar tools, shortcuts, and extensions while executing code on remote Databricks compute resources.

*   **Unified Environment:** Develop in VS Code using your preferred themes, keybindings, and productivity tools.
*   **Remote Execution:** Run notebooks, test Python scripts, and deploy workflows without leaving your editor.
*   **Distributed Power:** Maintain a lightweight local setup while tapping into the scalable compute power of Azure Databricks clusters or SQL warehouses.

### Key Benefits

| Feature | Benefit |
| :--- | :--- |
| **Direct Connectivity** | Eliminates manual file uploads and copy-paste workflows. |
| **Interactive Debugging** | Step through code locally while it executes on remote clusters. |
| **Version Control Friendly** | Manage notebook source code as standard files in your local Git repository. |
| **Consistent Tooling** | Use the same linters, formatters, and IntelliSense features you rely on for other Python or SQL projects. |

> [!NOTE]
> By integrating VS Code with Azure Databricks, you create a more efficient, professional development environment that supports modern software engineering practices—such as version control and automated testing—while still leveraging the massive scale of the Lakehouse platform.

## Develop locally and execute remotely
Visual Studio Code (VS Code) provides a robust local development environment featuring IntelliSense, syntax highlighting, and deep Git integration. The **[Databricks extension](https://marketplace.visualstudio.com/items?itemName=databricks.databricks)** extends this capability by enabling the execution of local code on remote Azure Databricks clusters or serverless compute resources.

### Local-to-Remote Execution

The extension eliminates the friction of manual file transfers and context switching. You can write code in standard `.py` files or Databricks notebooks on your local machine and execute them directly against Azure Databricks infrastructure.

*   **Seamless Workflow:** Develop locally using your preferred editor features while leveraging the distributed power of Databricks.
*   **Multi-Language Support:** Execute Python, R, Scala, and SQL code without leaving the VS Code interface.
*   **No Manual Copying:** Changes made locally are synchronized and executed remotely, ensuring a consistent development loop.

### Lakeflow Jobs

Beyond interactive execution, the extension supports the packaging and deployment of notebooks as **Lakeflow Jobs**.

*   **Job Orchestration:** Run notebooks on a schedule or via event triggers rather than just interactively.
*   **Pre-Deployment Testing:** Test job configurations and dependencies locally before committing them to source control, bridging the gap between development and production environments.

### Multi-Project Management

The extension is designed for complex development scenarios, supporting multiple Databricks projects within a single VS Code workspace.

*   **Context Switching:** Easily switch between different Databricks environments, modules, or workspaces without closing and reopening folders.
*   **Isolated Configurations:** Each project maintains its own:
    *   Workspace connection details.
    *   Authentication settings.
    *   Cluster or serverless compute selection.

> [!NOTE]
> This multi-project support is particularly valuable for data engineers managing distinct development, staging, and production environments, or for teams working on multiple unrelated data pipelines simultaneously.

## Debug Code with Databricks Connect

The Databricks extension integrates **Databricks Connect** to bring full-featured debugging capabilities directly into Visual Studio Code. This integration bridges the gap between local development tools and remote distributed computing, allowing you to troubleshoot complex data pipelines with precision.

### How It Works

Databricks Connect establishes a direct link between your local Python environment and a remote Azure Databricks cluster. When you initiate a debug session:

1.  **Local Control:** The Python debugger in VS Code controls the execution flow on the remote cluster.
2.  **Remote Execution:** Your code runs on Databricks compute, leveraging distributed data and Spark APIs.
3.  **Interactive Inspection:** You can set breakpoints, inspect variables, and step through code exactly as you would with a local script.

### Debugging Notebooks and Files

This environment supports both standard Python files (`.py`) and Databricks notebooks (`.ipynb` or `.dbc`).

*   **Cell-by-Cell Debugging:** For notebooks, you can debug individual cells, examining the state of DataFrames and variables at each step of your transformation logic.
*   **Rapid Iteration:** When an error occurs, you can modify the code locally, set a breakpoint before the problematic line, and rerun the debugger immediately. This tight feedback loop significantly reduces the time spent troubleshooting distributed transformations.

### Unit Testing with pytest

Beyond interactive debugging, the extension supports running unit tests using **pytest** on Databricks compute.

*   **Environment Consistency:** Tests execute against the same dependencies, libraries, and Spark configuration as your production code.
*   **Early Detection:** This ensures that environment-specific issues—such as library version conflicts or Spark API incompatibilities—are caught during development rather than in production.

> [!NOTE]
> By enabling local debugging and remote testing within a single interface, Databricks Connect transforms the development experience from a "write-and-hope" workflow into a rigorous, engineering-grade process.

## Deploy Workflows with Declarative Automation Bundles

The Databricks extension for Visual Studio Code streamlines the deployment process through **Declarative Automation Bundles** (formerly known as Databricks Asset Bundles). This approach transforms infrastructure and workflow configuration into code, allowing you to package your notebooks, scripts, configurations, and dependencies into version-controlled, deployable units.

### Defining Infrastructure as Code

Bundles use YAML configuration files to define the structure of your data engineering and ML workflows. Within these files, you specify:

*   **Lakeflow Jobs:** Task sequences, schedules, and triggers.
*   **Lakeflow Spark Declarative Pipelines (SDP):** Data ingestion and transformation logic.
*   **MLOps Stacks:** Model training, evaluation, and serving configurations.
*   **Compute Settings:** Cluster types, sizes, and runtime versions.
*   **Dependencies:** Task ordering and resource requirements.

> [!NOTE]
> The extension provides a dedicated UI within VS Code for creating, validating, and deploying these bundles, eliminating the need to switch between your editor and the web-based workspace UI for routine deployment tasks.

### Targeted Deployment

When you are ready to promote your work, the extension applies the bundle to a specific target environment—such as **development**, **staging**, or **production**. During this process, it:

1.  Creates or updates Lakeflow Jobs and pipelines.
2.  Provisions or configures the required compute resources.
3.  Sets up necessary permissions and access controls according to your specifications.

This declarative model ensures that every environment is configured consistently, reducing "drift" and manual errors common in traditional deployment methods.

### Version Control and CI/CD Integration

By treating workflow configuration as code, you can version your entire pipeline alongside your Python or SQL scripts in Git.

*   **Unified Review Process:** Changes to job schedules, cluster sizes, or task dependencies go through the same pull request and approval workflows as your application code.
*   **Audit Trail:** Every change to production infrastructure is tracked, providing a clear history of who changed what and when.
*   **CI/CD Enablement:** Bundles are designed to integrate seamlessly with continuous integration and continuous deployment pipelines, automating the promotion of validated workflows from development to production.

> [!IMPORTANT]
> Adopting Declarative Automation Bundles shifts data engineering from ad-hoc management to a rigorous software engineering practice. It ensures that your production environments are reproducible, auditable, and easily scalable.

## Synchronize code between local and remote workspaces

While Declarative Automation Bundles are the standard for structured deployment, the Databricks extension also supports **one-way automatic synchronization** for rapid prototyping and collaborative development. This feature bridges the gap between local editing and remote execution, allowing you to maintain a fast feedback loop during the early stages of development.

### How Synchronization Works

The extension monitors your local Visual Studio Code project and automatically uploads changes to designated directories in your Azure Databricks workspace.

*   **Local-to-Remote Flow:** Edits made locally are instantly reflected in the workspace.
*   **Transient Workspace Files:** The files in the workspace are treated as transient mirrors of your local code. You should **avoid making changes directly in the workspace**, as these modifications will not sync back to your local project and may be overwritten by the next automatic upload.
*   **Source of Truth:** Your local project remains the single source of truth for version control and Git integration.

### Strategic Use Cases

| Scenario | Recommended Approach | Why? |
| :--- | :--- | :--- |
| **Exploratory Development** | Code Synchronization | Allows for quick iterations and immediate testing on remote clusters without the overhead of bundle deployment. |
| **Team Transition** | Code Synchronization | Helps teams moving from web-based notebook development to local IDEs maintain their existing workspace structures while adopting Git. |
| **Production Deployment** | Declarative Automation Bundles | Provides rigorous control, environment-specific configurations, and auditability required for stable, repeatable pipelines. |

> [!NOTE]
> Synchronization is best viewed as a development aid rather than a deployment strategy. It excels at supporting agile, iterative work where speed is prioritized over structural rigidity. For any workflow that requires stability, governance, or multi-environment promotion, transition to **Declarative Automation Bundles** to ensure consistency and control.
