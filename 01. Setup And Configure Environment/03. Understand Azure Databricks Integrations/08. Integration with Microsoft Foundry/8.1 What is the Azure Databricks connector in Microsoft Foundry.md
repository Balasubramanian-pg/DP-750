## What is the Azure Databricks connector in Microsoft Foundry

Microsoft Foundry enhances AI agents by integrating external tools through standardized connectors. The **Azure Databricks Genie connector** serves as a bridge, allowing agents to access curated datasets and business intelligence insights directly from the Lakehouse. This integration transforms static data into dynamic, conversational knowledge.

### The Role of Genie Spaces

The connector operates through **Genie spaces**, which are specialized conversational interfaces built on top of Azure Databricks data. Rather than exposing raw tables, Genie spaces provide a governed, pre-configured layer for interaction.

*   **Expert Configuration:** Domain experts define the scope of each space by selecting specific datasets, providing sample queries, and establishing business terminology.
*   **Natural Language Interface:** When added as a tool in Microsoft Foundry, a Genie space enables agents to answer questions about that data using plain language, removing the need for users to understand SQL or database schemas.

### Abstraction and Governance

A key benefit of this integration is the layer of abstraction it provides between the AI agent and the underlying data infrastructure.

*   **Indirect Querying:** Microsoft Foundry agents do not query raw tables or generate SQL directly. Instead, they interact with the Genie space, which handles the translation of natural language into optimized SQL queries.
*   **Simplified Integration:** This approach reduces the complexity of connecting AI to structured data while ensuring that all interactions remain within the boundaries defined by the Genie space configuration.
*   **Governed Access:** Because the Genie space is built on Unity Catalog, all data access is subject to existing governance policies, including row-level security and column masking.

### The Model Context Protocol (MCP)

The technical foundation of this integration is the **Model Context Protocol (MCP)**, an open standard that defines how AI agents communicate with external tools and data sources.

*   **Managed Servers:** Azure Databricks implements MCP through managed servers that expose resources such as Genie spaces, Unity Catalog functions, and other data assets.
*   **Client-Server Interaction:** Microsoft Foundry acts as an **MCP client**, sending structured requests to the Azure Databricks MCP server. The server processes these requests against the Genie space and returns structured responses, enabling seamless, real-time data retrieval within the agent’s workflow.

> [!NOTE]
> By leveraging MCP, this integration ensures interoperability and scalability. As the ecosystem of MCP-compatible tools grows, Microsoft Foundry agents will be able to interact with an expanding range of Azure Databricks resources beyond just Genie spaces, including custom functions and metadata catalogs.
