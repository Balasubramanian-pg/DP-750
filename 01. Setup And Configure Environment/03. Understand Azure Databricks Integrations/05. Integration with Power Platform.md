# Integration with Power Platform

## Power Platform Integration with Azure Databricks

The Microsoft Power Platform empowers users to build custom applications, automate workflows, and analyze data with minimal coding. Integrating this suite with Azure Databricks bridges the gap between high-performance data engineering and agile business application development. This connection allows organizations to leverage governed, high-quality data from the Lakehouse directly within the tools business users rely on daily.

### The Azure Databricks Connector

The integration is facilitated by the **Azure Databricks connector**, which serves as a secure bridge between Power Platform services and your Unity Catalog-managed data. This connector enables:

*   **Power Apps:** To read from and write to Unity Catalog tables, allowing for the creation of data-driven business applications.
*   **Power Automate:** To trigger and orchestrate complex data workflows, including the execution of Databricks jobs or notebooks based on business events.

### Governance and Security

A critical advantage of this integration is the preservation of existing security policies. Because the connector interacts directly with Unity Catalog:

1.  **Centralized Control:** Access controls, row-level filters, and column masks defined in Databricks are enforced when Power Platform services access the data.
2.  **Secure Data Flow:** Business users can interact with sensitive data through approved applications without requiring direct access to the underlying storage or compute infrastructure.
3.  **Auditability:** All data interactions initiated from Power Platform are logged within the Databricks audit trail, ensuring compliance and visibility.

> [!NOTE]
> This integration transforms Azure Databricks from a backend engineering platform into a foundational data source for the entire organization. By empowering business users to build solutions on top of governed data, you reduce shadow IT risks while accelerating the delivery of actionable insights and automated processes.

## Connect Power Platform to Azure Databricks

Integrating Power Platform with Azure Databricks requires a **premium connector** that bridges business applications with the Lakehouse. This connection relies on specific infrastructure and authentication configurations to ensure secure, high-performance data access.

### Prerequisites

Before establishing a connection, ensure the following requirements are met:

*   **Licensing:** A premium Power Apps or Power Automate license is required to use the premium connector.
*   **Identity:** A Microsoft Entra ID account for authentication.
*   **Compute Resource:** Access to a **Databricks SQL Warehouse**. SQL warehouses are the preferred compute resource because they provide optimized query performance and serverless scaling specifically designed for analytical workloads.

### Authentication Methods

The connector supports two distinct authentication types, each suited for different operational scenarios:

| Method | Description | Best For |
| :--- | :--- | :--- |
| **OAuth Connection** | Uses Microsoft Entra ID to authenticate individual users. | Interactive apps where user-level permissions and auditing are required. |
| **Service Principal** | Uses fixed credentials (Client ID and Secret) for authentication. | Automated workflows, background processes, or apps where a consistent, non-user identity is preferred. |

### Configuration Steps

To establish the connection in Power Apps or Power Automate:

1.  Navigate to the **Connections** page and search for the **Azure Databricks** connector.
2.  Select your preferred authentication method (OAuth or Service Principal).
3.  Provide the following connection details from your SQL warehouse:
    *   **Server Hostname:** The unique address of your SQL warehouse.
    *   **HTTP Path:** The specific path that identifies the warehouse endpoint.

> [!NOTE]
> You can find the Server Hostname and HTTP Path in the **Connection details** section of your SQL warehouse within the Azure Databricks workspace.

### Network Connectivity

If your Azure Databricks workspace is secured within a virtual network (VNet), you must configure network access to allow the Power Platform connector to communicate with your SQL warehouse:

*   **VNet Peering:** Establish private connectivity between the Power Platform infrastructure and your Azure VNet.
*   **IP Access Lists:** Configure your workspace to allow traffic from the specific **AzureConnectors IP ranges**.

> [!IMPORTANT]
> Without proper network configuration, the Power Platform connector will be unable to reach your SQL warehouse, resulting in connection timeouts or authentication failures. Always verify network rules before attempting to create the connection.

## Build applications with Power Apps

Power Apps enables the creation of custom canvas and model-driven applications that interact directly with data stored in Azure Databricks. This integration transforms the Lakehouse from a backend analytics engine into a dynamic source for business-facing interfaces, supporting data entry, approval workflows, and interactive dashboards.

### Canvas Apps: Direct Data Interaction

When building canvas apps, you connect directly to Unity Catalog to select specific catalogs and tables. This direct connection supports full CRUD (Create, Read, Update, Delete) operations, allowing users to modify lakehouse data through intuitive forms.

*   **Real-Time Governance:** When using **OAuth authentication**, Unity Catalog evaluates each user’s permissions in real time. This ensures that row-level security filters, column masks, and table access controls are strictly enforced within the app interface.
*   **Security Without Compromise:** Business users can interact with trusted, governed data without requiring direct access to the underlying storage or compute infrastructure.

### Model-Driven Apps: Virtual Tables

For scenarios requiring structured forms, complex views, and deep business logic, Power Apps supports **Dataverse virtual tables** backed by Azure Databricks data.

*   **No Data Duplication:** Virtual tables integrate Databricks data into the Microsoft Dataverse ecosystem without physically copying it, saving on storage costs.
*   **Unified Experience:** Allows you to build model-driven apps that treat Databricks data as if it were native Dataverse data, leveraging standard Power Platform features like relationships and business rules.

> [!TIP]
> **Performance Consideration**
> For optimal query response times, prefer **direct connections** over virtual tables whenever possible. While virtual tables offer architectural benefits by avoiding data duplication, direct connections typically provide faster performance for interactive app experiences.

### Handling Bulk Operations with Power Automate

While canvas apps are excellent for individual record interactions, they are not optimized for large-scale data modifications. For bulk updates, integrate **Power Automate flows**:

*   **Batch Processing:** Flows can process multiple changes in a single batch, significantly improving efficiency compared to individual API calls from a canvas app.
*   **Workflow Orchestration:** Use flows to trigger complex multi-step processes, such as validating data in Databricks before committing changes or triggering downstream jobs upon data submission.

> [!NOTE]
> By combining canvas apps for user interaction, virtual tables for structured logic, and Power Automate for bulk processing, you can create comprehensive business solutions that are both secure and performant, all built on the foundation of your governed Azure Databricks data.

## Automate workflows with Power Automate

Power Automate enables the creation of automated workflows that bridge business processes with data operations in Azure Databricks. Through the Azure Databricks connector, you can orchestrate complex pipelines, respond to real-time events, and coordinate data processing tasks without writing custom code.

### Core Capabilities

The connector exposes two primary mechanisms for interacting with Databricks:

#### 1. SQL Statement Execution
You can write and execute SQL queries directly within a flow, leveraging Databricks SQL warehouses for high-performance analytics.

*   **Flexible Triggers:** Initiate queries via schedules, manual buttons, or events from other services (e.g., when a new file lands in storage).
*   **Result Handling:** Retrieve query results for use in subsequent steps, such as sending email summaries or updating records in other systems.
*   **Chunked Retrieval:** Supports handling large result sets efficiently by retrieving data in manageable chunks, preventing memory overflow in the flow engine.

#### 2. Job Orchestration
Trigger and manage existing **Lakeflow Jobs** or notebooks directly from your business workflows.

*   **Lifecycle Management:** Start a job run, track its progress in real time, and retrieve metadata including status, start/end times, and execution duration.
*   **Control Actions:** Cancel running statements or jobs if conditions change, and list available jobs for dynamic selection.
*   **Output Retrieval:** Access the output of completed runs to drive downstream logic, such as conditional branching based on success or failure.

### Strategic Use Cases

| Scenario | Implementation | Benefit |
| :--- | :--- | :--- |
| **Event-Driven Processing** | Trigger a Databricks job when new data arrives in Azure Blob Storage. | Ensures data is processed immediately upon ingestion, reducing latency. |
| **Data Quality Alerts** | Run a quality check job and send a Teams notification if errors exceed a threshold. | Provides proactive monitoring and rapid response to data issues. |
| **Automated Retries** | Use conditional logic to retry a failed job up to three times before alerting an admin. | Increases pipeline resilience without manual intervention. |
| **Cross-Platform Pipelines** | Combine Databricks processing with Power Apps updates or SharePoint notifications. | Creates end-to-end business solutions that span data engineering and user interaction. |

> [!IMPORTANT]
> **Throttling Limits**
> The Power Platform connector operates under specific throttling limits to ensure service stability. When designing flows that process large volumes of data or trigger frequent jobs:
> *   **Batch Operations:** Group multiple actions where possible to reduce the number of API calls.
> *   **Delay Steps:** Introduce appropriate delays between high-frequency operations to stay within rate limits.
> *   **Monitor Usage:** Regularly review flow run history to identify and optimize bottlenecks.

By integrating Power Automate with Azure Databricks, you extend the reach of your data pipelines into the broader business ecosystem, enabling automated, responsive, and governed data-driven processes.

## Integration scenarios
The Azure Databricks and Power Platform integration enables several practical scenarios that bridge the gap between data engineering and business operations. Consider a planning and forecasting application where business users submit next month's forecasts, adjust revenue targets, or update budget allocations through a Power App that writes directly to a Unity Catalog table. With OAuth authentication and Unity Catalog governance, each user sees only the data they're authorized to access, and all changes are tracked in the table's audit log.
Another scenario involves automated data quality workflows. You build a Power Automate flow that runs on a schedule, executes a SQL query to check data quality metrics, and sends notifications to the data team when quality thresholds are exceeded. The flow can also trigger a Databricks job to repair data issues automatically or escalate to a human review process based on the severity of the issue.
For event-driven data processing, you create a flow that monitors a business system for events—such as a new customer order or a completed transaction—and triggers a Databricks job to process the associated data. The flow passes relevant parameters to the job, waits for completion, and updates the business system with the results. This pattern enables real-time data integration without building custom integration code.
Dashboard refresh automation represents another valuable use case. You schedule a Power Automate flow that executes SQL to prepare aggregated data, stores the results in a table, and triggers a refresh of a business intelligence dashboard. This approach provides business users with up-to-date insights without manual intervention from the data team.
These scenarios become possible because the integration preserves governance while enabling access. Unity Catalog continues to enforce all security policies, data masking, and access controls even when data flows through Power Platform. Business users gain the ability to work with data through familiar interfaces while data engineers maintain centralized control over data quality, security, and compliance.

## Considerations and limitations
While the Azure Databricks Power Platform connector provides broad capabilities, some considerations affect how you design your solutions. The connector doesn't support government clouds, including US Government and China Cloud environments. Organizations operating in these environments need alternative integration approaches.
Within Power Apps, certain PowerFx formulas calculate values using only data that has been retrieved locally to the app, rather than delegating computation to Azure Databricks. For large datasets, this can affect performance and accuracy. Consider filtering data or performing aggregations in SQL within Azure Databricks before bringing data into Power Apps.
Concurrent write operations from multiple Power Apps users or flows benefit from row-level concurrency features in Azure Databricks. These features are available in recent Databricks Runtime versions and help reduce write conflicts when multiple users modify data simultaneously.
When choosing between virtual tables and direct connections, consider the trade-offs. Virtual tables enable model-driven apps and integrate with the broader Dataverse ecosystem, but they don't support OAuth credential passthrough. Direct connections offer better performance and support OAuth for governance passthrough, but they only work with canvas apps. Choose the approach that best fits your application architecture and governance requirements.
Finally, data policies in Power Platform affect connector usage. You can add the Azure Databricks connector to a Business data policy to control which other connectors can share data with it, helping you maintain compliance with data handling regulations.
