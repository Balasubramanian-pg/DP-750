# Integration with Power BI
## Power BI Integration with Azure Databricks

Power BI provides interactive visualizations and business intelligence capabilities that extend the value of data managed in Azure Databricks. This integration enables users across various roles—from data engineers to business analysts—to create reports and dashboards directly from governed Databricks data. The connection is facilitated through multiple methods, each supporting different authentication options and usage scenarios.

### Connection Methods

You can integrate Power BI with Azure Databricks using three primary approaches:

1.  **Power BI Desktop:** Connect directly to compute resources for report development.
2.  **Direct Publishing:** Publish datasets and reports from Azure Databricks directly to the Power BI service.
3.  **Unity Catalog Orchestration:** Manage semantic model refreshes and connections through centralized Unity Catalog configurations.

### Power BI Desktop Connectivity

Power BI Desktop is a Windows-based application used to build interactive reports. It supports connections to both **Azure Databricks clusters** and **Databricks SQL warehouses**. For optimal performance and serverless scaling, **SQL warehouses** are the recommended compute resource.

#### Establishing a Connection
*   **Partner Connect (Recommended):** The fastest method. From the Azure Databricks workspace Marketplace, select the Power BI tile, choose your compute resource, and download a preconfigured connection file. This file automatically opens Power BI Desktop with the correct settings.
*   **Manual Configuration:** Enter the **Server Hostname** and **HTTP Path** from your compute resource details directly into the Power BI connector.

#### Data Connectivity Modes
After connecting, you must choose how Power BI interacts with your data:

| Mode | Description | Best For |
| :--- | :--- | :--- |
| **Import Mode** | Loads data into Power BI’s internal storage engine. Enables fast queries but requires periodic refreshes to stay current. | Static datasets or when high-performance visuals are needed without constant database load. |
| **DirectQuery Mode** | Queries Azure Databricks directly for every visualization interaction. Ensures real-time data access but requires an active, running compute resource. | Large datasets that cannot be imported or scenarios requiring up-to-the-minute data accuracy. |

> [!NOTE]
> **Arrow Database Connectivity (ADBC)**
> Since February 2026, all new Power BI connections to Azure Databricks use the **ADBC driver** by default. ADBC is a modern, columnar API standard based on Apache Arrow that offers significantly more efficient data transfer for analytical workloads.
>
> *   **Existing Connections:** Continue to use ODBC unless manually updated.
> *   **Updating to ADBC:** Set `Implementation="2.0"` in the Advanced Editor in Power BI Desktop.
> *   **Compatibility:** Always test existing semantic models against ADBC before updating to ensure full compatibility.

### Authentication Options

The method of authentication determines how Power BI accesses your data and how permissions are enforced:

*   **Microsoft Entra ID (SSO):** Enables single sign-on where individual user credentials are passed through to Azure Databricks. This allows **Unity Catalog** to enforce fine-grained, user-level permissions.
*   **Personal Access Tokens:** Provide simple authentication but represent a single user identity. Less secure for shared reports.
*   **Service Principals (OAuth):** Provide fixed, machine-to-machine credentials. Ideal for automated refreshes and scenarios where user context is not required.

### Advanced Features and Requirements

*   **Native SQL Queries:** Power BI Desktop supports writing native SQL directly against your Databricks SQL warehouse. This bypasses the visual query builder, giving you full control over query optimization and access to Databricks-specific SQL features for compute-intensive operations.
*   **Operating System Requirement:** Power BI Desktop requires **Windows**. If you use macOS or Linux, you must run Power BI Desktop on a Windows-based virtual machine and connect to it remotely.

## Publish to the Power BI service from Azure Databricks

The Power BI service serves as the cloud-based platform for sharing reports and collaborating across your organization. Rather than initiating connections from Power BI Desktop, you can publish data directly from the Azure Databricks UI. This workflow streamlines deployment by leveraging Unity Catalog as the source of truth for metadata and governance.

### The Publishing Workflow

Publishing is initiated through **Catalog Explorer** within your Azure Databricks workspace:

1.  Select a schema or specific tables registered in Unity Catalog.
2.  Choose **Publish to Power BI workspace**.
3.  Authenticate via Microsoft Entra ID when prompted.
4.  Configure the target Power BI workspace, connectivity mode (DirectQuery or Import), and authentication settings.

When publishing a schema containing multiple tables, Databricks automatically creates a semantic model in the designated Power BI workspace. Metadata preservation includes:

-   **Column Descriptions:** Comments from Unity Catalog tables transfer directly to Power BI column descriptions.
-   **Relationships:** Foreign key relationships are transferred. However, because Power BI supports only one active relationship path between any two tables, some relationships may become inactive if multiple paths exist.

### Licensing and Infrastructure Requirements

This integration method has specific prerequisites that must be met before publishing:

| Requirement | Details |
| :--- | :--- |
| **Unity Catalog** | Mandatory for data governance and metadata synchronization. |
| **Premium Capacity** | Requires Power BI Premium (Capacity or Per User) or Microsoft Fabric capacity. |
| **XMLA Endpoint** | Must be enabled with **Read and Write** capabilities in your Power BI/Fabric capacity settings. |

> [!IMPORTANT]
> The Premium license provides the necessary capacity for enterprise scenarios and enables the **XMLA (XML for Analysis) endpoint**. Databricks relies on this endpoint to programmatically create and update semantic models during the publishing process. Without Read/Write access enabled, publishing will fail.

### Authentication and Governance Enforcement

How you configure authentication determines whether Unity Catalog’s fine-grained policies are enforced for downstream users.

#### User-Level Security (Recommended)
Use **OAuth authentication** for published semantic models to maintain governance consistency. When users access a report built on DirectQuery mode:
-   Power BI passes their individual Microsoft Entra ID credentials to Azure Databricks.
-   Unity Catalog evaluates permissions for that specific user.
-   Row-level filters, column masks, and table access controls are enforced dynamically.

#### Automated and Shared Access
For scenarios requiring scheduled refreshes or shared credentials, configure **machine-to-machine OAuth** using service principals:
-   Edit the semantic model's data source credentials in the Power BI service.
-   Provide the service principal's client ID and secret.
-   This method works with both standard semantic models and Power BI gateways for private network scenarios.

> [!NOTE]
> While service principals simplify automation, they bypass user-level Unity Catalog enforcement. Reserve this approach for trusted, automated workflows where individual user auditing is not required. For interactive reporting, always prefer OAuth pass-through to ensure security policies travel with the data.

## Automate Power BI Publishing with Power BI Tasks

While manual publishing from the Azure Databricks UI is effective for initial setup, **Power BI tasks** enable you to orchestrate semantic model publishing and refreshes automatically within your Databricks workflows. This integration ensures that business intelligence assets remain synchronized with upstream data transformations, eliminating the need for manual intervention and reducing the risk of reporting on stale data.

### Unity Catalog Connections

To use Power BI tasks, you must first establish a **Unity Catalog connection** to Power BI. This connection object stores the necessary authentication credentials and workspace configuration, allowing tasks to interact with the Power BI service programmatically.

You can choose from three authentication methods based on your security and operational requirements:

*   **Service Credentials:** Uses a fixed identity for consistent, automated access.
*   **OAuth Machine-to-Machine:** Leverages service principals for secure, non-interactive authentication.
*   **OAuth User-to-Machine:** Allows tasks to run under the context of a specific user, useful for auditing or testing.

### Workflow Orchestration

Power BI tasks integrate seamlessly into Databricks workflows alongside data engineering notebooks, SQL queries, and machine learning training jobs. By defining task dependencies, you can control the execution order to ensure data integrity.

**Example Automated Pipeline:**

1.  **Ingestion Task:** A notebook ingests raw data from external sources into Unity Catalog tables.
2.  **Transformation Task:** A SQL task processes the raw data into curated, analytics-ready tables.
3.  **Power BI Task:** Automatically publishes the curated tables to a Power BI semantic model and triggers a data refresh.

> [!NOTE]
> In this sequence, the Power BI semantic model only refreshes after the upstream data updates have completed successfully. This dependency chain guarantees that your reports always reflect the most recent, validated data without requiring manual scheduling or monitoring.

### Benefits of Automation

*   **Data Consistency:** Ensures reports are never refreshed before the underlying data is ready.
*   **Operational Efficiency:** Reduces manual effort by embedding BI updates into existing ETL/ELT pipelines.
*   **Governance:** Maintains a clear lineage from raw data ingestion to final report visualization within a single orchestrated workflow.

## Choosing the Right Integration Method

Selecting the appropriate integration pattern depends on your specific workflow, security requirements, and the division of labor between data engineers and business analysts. Each method serves a distinct purpose in the end-to-end analytics lifecycle.

### Integration Patterns by Use Case

| Method | Primary Use Case | Key Benefits |
| :--- | :--- | :--- |
| **Power BI Desktop** | Interactive exploration and report authoring by business analysts. | Provides a flexible drag-and-drop environment; allows combining multiple data sources; supports both Import and DirectQuery modes. |
| **Publish from Databricks** | Sharing curated, governed datasets initiated by data engineers. | Ensures engineering teams control which tables are exposed; automatically transfers metadata (column descriptions) from Unity Catalog to Power BI. |
| **Power BI Tasks** | Automating semantic model refreshes within data pipelines. | Coordinates BI updates with upstream ETL/ELT jobs; ensures reports only refresh after source data processing is complete. |
| **Power BI Gateway** | Secure connectivity for private network environments. | Enables access to Azure Databricks workspaces protected by private endpoints or IP access lists without exposing them to the public internet. |

### Private Network Connectivity

For organizations with strict network security mandates, **Power BI Gateways** provide a secure bridge between the Power BI service and private Azure Databricks environments.

*   **Configuration:** You install and configure an on-premises or virtual network gateway with your Azure Databricks connection details and authentication credentials.
*   **Routing:** The Power BI service routes queries through the gateway, which then connects to your private Azure Databricks workspace.
*   **Security:** This approach eliminates the need to expose Databricks endpoints publicly, maintaining compliance with enterprise network isolation policies.

> [!NOTE]
> In many mature architectures, these methods are not mutually exclusive. An organization might use **Power BI Desktop** for initial prototyping, **Publish from Databricks** for production-grade curated datasets, and **Power BI Tasks** to ensure those datasets remain current as part of an automated nightly pipeline.
