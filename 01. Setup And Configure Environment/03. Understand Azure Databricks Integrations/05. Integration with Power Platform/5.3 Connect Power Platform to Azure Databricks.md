## Connect Power Platform to Azure Databricks

Integrating Power Platform with Azure Databricks requires a **premium connector** that bridges business applications with the Lakehouse. This connection relies on specific infrastructure and authentication configurations to ensure secure, high-performance data access.

### Prerequisites

Before establishing a connection, ensure the following requirements are met:

*   **Licensing:** A premium Power Apps or Power Automate license is required to use the premium connector.
*   **Identity:** A Microsoft Entra ID account for authentication.
*   **Compute Resource:** Access to a **Databricks SQL Warehouse**. SQL warehouses are the preferred compute resource because they provide optimized query performance and serverless scaling specifically designed for analytical workloads.

### Authentication Methods

The connector supports two distinct authentication types, each suited for different operational scenarios:

| Method | Description | Best For |
| :--- | :--- | :--- |
| **OAuth Connection** | Uses Microsoft Entra ID to authenticate individual users. | Interactive apps where user-level permissions and auditing are required. |
| **Service Principal** | Uses fixed credentials (Client ID and Secret) for authentication. | Automated workflows, background processes, or apps where a consistent, non-user identity is preferred. |

### Configuration Steps

To establish the connection in Power Apps or Power Automate:

1.  Navigate to the **Connections** page and search for the **Azure Databricks** connector.
2.  Select your preferred authentication method (OAuth or Service Principal).
3.  Provide the following connection details from your SQL warehouse:
    *   **Server Hostname:** The unique address of your SQL warehouse.
    *   **HTTP Path:** The specific path that identifies the warehouse endpoint.

> [!NOTE]
> You can find the Server Hostname and HTTP Path in the **Connection details** section of your SQL warehouse within the Azure Databricks workspace.

### Network Connectivity

If your Azure Databricks workspace is secured within a virtual network (VNet), you must configure network access to allow the Power Platform connector to communicate with your SQL warehouse:

*   **VNet Peering:** Establish private connectivity between the Power Platform infrastructure and your Azure VNet.
*   **IP Access Lists:** Configure your workspace to allow traffic from the specific **AzureConnectors IP ranges**.

> [!IMPORTANT]
> Without proper network configuration, the Power Platform connector will be unable to reach your SQL warehouse, resulting in connection timeouts or authentication failures. Always verify network rules before attempting to create the connection.
