## Considerations and Limitations

Implementing Copilot Studio agents with Azure Databricks requires careful planning to ensure performance, security, and cost-efficiency. While the integration is powerful, it operates within specific technical and environmental boundaries.

### Environmental and Infrastructure Constraints

*   **Cloud Support:** The connector is **not supported** in sovereign cloud environments, including US Government (GCC, GCC High) and China Cloud regions.
*   **Compute Requirements:** Genie integration requires a **SQL Warehouse** (Serverless or Pro). Classic compute clusters are not supported for Genie spaces.
    *   **Optimization:** Because agents often generate many small, concurrent queries, configure your SQL warehouse with **auto-scaling** to handle burst traffic and **auto-stop** to minimize costs during idle periods.

### Data Structure and Performance

The quality of an agent’s responses is directly tied to the structure of the underlying data.

*   **Schema Design:** Use clear, business-friendly column names and consistent data types. Ambiguous technical identifiers can lead to misinterpretation by the AI model.
*   **Simplified Views:** Avoid exposing complex schemas with multiple joins directly to the agent. Instead, create **dedicated, curated views** or aggregated tables specifically for agent consumption. This reduces query complexity and improves response accuracy.
*   **Indexing:** Ensure appropriate indexing on frequently queried columns to speed up retrieval times.

### Authentication and Governance Trade-offs

The choice of authentication method dictates how governance is enforced:

| Method | Governance Model | Requirement |
| :--- | :--- | :--- |
| **OAuth** | **User-Level:** Enforces row-level security and column masking based on the individual user’s identity. | Users must have Azure Databricks permissions, and both platforms must reside in the same Microsoft Entra tenant. |
| **Service Principal** | **Service-Level:** All queries run with the principal’s fixed permissions. | Provides consistent access but **bypasses user-level row security**. Best for uniform data access scenarios. |

### Throttling and Cost Management

Power Platform connectors operate under strict rate limits to ensure service stability.

*   **API Limits:** The connector is subject to a limit of **100 API calls per 60 seconds**.
*   **Design Strategy:** To prevent throttling errors, design agents to batch operations where possible and cache frequently accessed information rather than querying the database for every identical request.
