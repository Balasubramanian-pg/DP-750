# Integration with Copilot Studio

Azure Databricks integrates with Microsoft Copilot Studio to bring governed lakehouse data into conversational AI agents. The Azure Databricks connector enables two integration patterns: knowledge sources for semantic search and question answering, and Genie spaces as intelligent analytical tools. Both approaches preserve Unity Catalog governance, ensuring users access only authorized data.

## Use tables as knowledge sources

## Copilot Studio Agents with Azure Databricks

Copilot Studio agents leverage Azure Databricks tables as dynamic knowledge sources, grounding their responses in your organization’s actual data. This integration allows users to ask questions in natural language and receive accurate, data-driven answers without needing to write SQL or understand complex data models.

### Configuration and Connectivity

To connect Copilot Studio to Azure Databricks, you configure a knowledge source that points to specific Unity Catalog assets. The agent queries these tables directly through a **Databricks SQL Warehouse**, ensuring that data remains in its original location and is not copied into the agent’s index.

**Authentication Options:**

| Method | Mechanism | Best For |
| :--- | :--- | :--- |
| **OAuth Authentication** | Passes each user’s Microsoft Entra ID identity to Azure Databricks. | Scenarios requiring strict, user-level enforcement of Unity Catalog permissions (row-level security, column masking). |
| **Service Principal** | Uses a fixed application identity for all queries. | Uniform data access where individual user context is not required, or for cross-tenant integrations. |

### How It Works: From Natural Language to SQL

The agent bridges the gap between human conversation and structured data through a multi-step process:

1.  **Semantic Translation:** The agent interprets the user’s natural language question and translates it into a valid SQL query.
2.  **Data Retrieval:** The SQL query is executed against the selected tables in the SQL Warehouse.
3.  **Synthesis:** The agent retrieves the relevant rows and synthesizes them into a conversational, easy-to-understand response.

> [!NOTE]
> **Governance Enforcement**
> Because the agent queries the SQL Warehouse directly, **Unity Catalog governance controls are fully enforced**. If a user asks for data they are not permitted to see, Unity Catalog will filter or mask the results in real time before the agent ever receives them.

### Optimizing for Agent Performance

While the integration is powerful, the quality of the agent’s responses depends heavily on the structure of the underlying data.

*   **Descriptive Naming:** Tables and columns should have clear, business-friendly names. Ambiguous technical identifiers can lead to misinterpretation by the AI model.
*   **Curated Views:** Consider creating dedicated views or aggregated tables specifically for agent consumption. These "agent-ready" datasets simplify the data model, reduce query complexity, and ensure the agent focuses on the most relevant metrics.
*   **Structured Data:** Well-structured, normalized data yields more accurate semantic search results than unstructured or highly nested formats.

> [!TIP]
> To maximize success, start with a small set of high-quality, well-documented tables. As you refine the agent’s performance, you can gradually expand the scope of accessible data while monitoring query accuracy and latency.

## Connect Genie Spaces as Tools

Copilot Studio agents can leverage **Genie spaces** as intelligent tools to perform advanced analytics beyond simple data retrieval. While knowledge sources ground an agent in static facts, Genie acts as a dynamic analytical engine capable of interpreting natural language questions, executing complex queries, and generating visualizations.

### The Role of Model Context Protocol (MCP)

This integration is powered by the **Model Context Protocol (MCP)**, a standard that enables seamless communication between AI agents and external data systems. MCP allows the Copilot Studio agent to orchestrate the flow between conversational management and analytical execution, ensuring that user questions are translated into precise analytical tasks within Azure Databricks.

### Genie vs. Knowledge Sources

Understanding the distinction between these two integration types is critical for designing effective agents:

| Feature | Knowledge Sources | Genie Spaces |
| :--- | :--- | :--- |
| **Primary Function** | Semantic search and factual retrieval. | Complex analytics, aggregation, and trend explanation. |
| **Output Type** | Text-based answers grounded in retrieved rows. | Analytical insights, charts, and visualizations. |
| **Engine** | Direct SQL query execution against tables. | Specialized AI-powered analytics engine. |
| **Use Case** | "What was the total revenue last month?" | "Show me the revenue trend by region and explain any anomalies." |

### Configuration Steps

To enable Genie as a tool for your Copilot Studio agent:

1.  **Enable Preview:** In your Azure Databricks workspace, enable the **Managed MCP Servers** preview feature.
2.  **Identify Space:** Locate the **Genie Space ID** for the specific analytics space you wish to connect.
3.  **Connect in Copilot Studio:** Add Genie as a tool in your agent’s configuration using the Space ID.
4.  **Orchestration:** The agent will now automatically route analytical questions to Genie, returning the resulting insights and visualizations directly into the conversation.

> [!IMPORTANT]
> **Public Preview Status**
> Genie integration via MCP is currently in **Public Preview**. While it offers powerful capabilities, features in preview are subject to change and may not yet meet the stability or support requirements of production workloads. Evaluate this integration carefully in non-production environments before widespread deployment.

## Integration Scenarios: Conversational AI with Governed Data

The integration of Copilot Studio with Azure Databricks enables a variety of high-impact scenarios where conversational AI meets enterprise-grade data governance. By leveraging both **Knowledge Sources** for factual retrieval and **Genie Spaces** for complex analytics, organizations can build agents that are not only intelligent but also secure and compliant.

### 1. Customer Support Agents
Support representatives often need quick access to specific customer details without navigating complex dashboards or writing SQL queries.

*   **Workflow:** An agent uses Unity Catalog tables as a knowledge source to answer questions about order history, inventory levels, or shipping status.
*   **Governance:** Unity Catalog enforces row-level security, ensuring that each representative sees only the orders and customer data they are authorized to access. This prevents data leakage while improving response times.

### 2. Executive Analytics Agents
Leadership teams require deep insights into business performance but may lack the time or technical skills to perform ad-hoc analysis.

*   **Workflow:** An agent connects to a **Genie Space** to handle complex analytical questions. For example, when asked, *"What drove the increase in customer churn last quarter?"*, the agent invokes Genie to analyze trends, identify contributing factors, and generate visualizations.
*   **Value:** This transforms static reporting into interactive, conversational discovery, allowing executives to drill down into data naturally.

### 3. Data Literacy Agents
As data estates grow, employees often struggle to find the right datasets or understand how metrics are defined.

*   **Workflow:** A data literacy agent answers meta-data questions such as, *"What tables contain customer demographic data?"* or *"How is revenue calculated in the sales fact table?"*
*   **Value:** By querying Unity Catalog metadata and documentation, these agents act as internal data guides, reducing the burden on data engineering teams and accelerating self-service analytics.

### 4. Compliance and Audit Agents
Responding to audit requests can be time-consuming and requires precise knowledge of data lineage and access controls.

*   **Workflow:** A compliance agent queries Unity Catalog metadata to provide instant answers about data lineage, access patterns, and governance policies.
*   **Value:** This automates the retrieval of audit trails, helping compliance teams respond efficiently to regulatory inquiries while maintaining a clear record of who accessed what data and when.

### The Governance Foundation

Across all these scenarios, the underlying security model remains consistent. Users interact through natural language, but **Unity Catalog** continues to enforce:

*   **Access Controls:** Ensuring users only see data they are permitted to view.
*   **Audit Logging:** Tracking every query and interaction for compliance.
*   **Data Masking:** Protecting sensitive information like PII from unauthorized exposure.

> [!NOTE]
> This integration model democratizes data access without sacrificing security. By embedding governance directly into the conversational interface, organizations can empower a wider range of employees to leverage their data assets confidently and responsibly.

## Considerations and Limitations

Implementing Copilot Studio agents with Azure Databricks requires careful planning to ensure performance, security, and cost-efficiency. While the integration is powerful, it operates within specific technical and environmental boundaries.

### Environmental and Infrastructure Constraints

*   **Cloud Support:** The connector is **not supported** in sovereign cloud environments, including US Government (GCC, GCC High) and China Cloud regions.
*   **Compute Requirements:** Genie integration requires a **SQL Warehouse** (Serverless or Pro). Classic compute clusters are not supported for Genie spaces.
    *   **Optimization:** Because agents often generate many small, concurrent queries, configure your SQL warehouse with **auto-scaling** to handle burst traffic and **auto-stop** to minimize costs during idle periods.

### Data Structure and Performance

The quality of an agent’s responses is directly tied to the structure of the underlying data.

*   **Schema Design:** Use clear, business-friendly column names and consistent data types. Ambiguous technical identifiers can lead to misinterpretation by the AI model.
*   **Simplified Views:** Avoid exposing complex schemas with multiple joins directly to the agent. Instead, create **dedicated, curated views** or aggregated tables specifically for agent consumption. This reduces query complexity and improves response accuracy.
*   **Indexing:** Ensure appropriate indexing on frequently queried columns to speed up retrieval times.

### Authentication and Governance Trade-offs

The choice of authentication method dictates how governance is enforced:

| Method | Governance Model | Requirement |
| :--- | :--- | :--- |
| **OAuth** | **User-Level:** Enforces row-level security and column masking based on the individual user’s identity. | Users must have Azure Databricks permissions, and both platforms must reside in the same Microsoft Entra tenant. |
| **Service Principal** | **Service-Level:** All queries run with the principal’s fixed permissions. | Provides consistent access but **bypasses user-level row security**. Best for uniform data access scenarios. |

### Throttling and Cost Management

Power Platform connectors operate under strict rate limits to ensure service stability.

*   **API Limits:** The connector is subject to a limit of **100 API calls per 60 seconds**.
*   **Design Strategy:** To prevent throttling errors, design agents to batch operations where possible and cache frequently accessed information rather than querying the database for every identical request.

> [!IMPORTANT]
> **Public Preview Status**
> Genie integration via the Model Context Protocol (MCP) is currently in **Public Preview**. Before deploying to production, carefully evaluate the stability requirements of your workload and enable the **Managed MCP Servers** preview feature in your workspace settings. Features in preview are subject to change and may not yet offer the same level of support as general availability features.
