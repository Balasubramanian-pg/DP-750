## How the integration works

The integration between Microsoft Foundry and Azure Databricks creates a powerful bridge between conversational AI and enterprise data. By leveraging the **Model Context Protocol (MCP)**, this architecture allows AI agents to access governed data through Genie spaces, enabling natural language interactions that are both accurate and secure.

### Architectural Components

The solution relies on three primary components working in concert:

1.  **Microsoft Foundry:** Hosts the AI agent, manages user interactions, and orchestrates tool usage.
2.  **Azure Databricks MCP Server:** Exposes Genie spaces as MCP-compatible tools, acting as the secure gateway for analytical queries.
3.  **Genie Spaces:** Contain the curated data, metadata, and business logic required to translate natural language into SQL and execute it against the Lakehouse.

### Runtime Workflow

When a user interacts with an agent in Microsoft Foundry, the following sequence occurs:

1.  **Routing:** Microsoft Foundry analyzes the user’s question and determines if it should be routed to the Genie tool based on context and configuration.
2.  **Transmission:** If invoked, Foundry sends the question to the Azure Databricks MCP server endpoint.
3.  **Processing:** The Genie space interprets the question, generates a SQL query, and executes it against the underlying data using a SQL warehouse.
4.  **Synthesis:** The results are returned to Microsoft Foundry, where the AI agent incorporates them into a conversational response for the user.

> [!NOTE]
> **Stateless Interaction**
> The Genie MCP server does not maintain conversation history when invoked as a tool. Each question is processed independently. For scenarios requiring multi-turn contextual awareness, you may need to explore alternative integration patterns or manage context within the agent’s prompt engineering.

### Authentication and Identity

Security is maintained through **OAuth Identity Passthrough**, ensuring that user identities flow securely from Microsoft Foundry to Azure Databricks.

*   **Managed OAuth (Recommended):** Uses Microsoft Entra ID for seamless, secure authentication.
*   **Custom OAuth:** Supports other identity providers for specific organizational requirements.
*   **Permission Validation:** Every time the agent accesses a Genie space, Azure Databricks validates that the requesting identity has the appropriate permissions to use that space and access the underlying data via Unity Catalog.

### Practical Use Cases

This integration enables several high-value scenarios:

| Scenario | Description | Benefit |
| :--- | :--- | :--- |
| **Live Data Assistants** | Agents answer business questions using real-time data from the Lakehouse. | Provides accurate, up-to-the-minute insights without manual reporting. |
| **Self-Service Analytics** | Business users ask questions in natural language without knowing SQL. | Democratizes data access while Genie handles query complexity. |

| **Multi-Tool Orchestration** | Agents combine Genie data retrieval with other tools for calculations or actions. | Creates comprehensive workflows that move from insight to action within a single conversation. |

### Configuration and Performance Optimization

The quality of the agent’s responses is heavily dependent on how the Genie space is configured.

*   **Expert Setup:** Domain experts should configure Genie spaces with relevant datasets, clear column descriptions, and sample queries that reflect common business questions.
*   **Compute Planning:** Genie uses **serverless SQL compute** to run queries. Performance depends on the complexity of the query and the size of the dataset. Configure auto-scaling to handle concurrency and auto-stop to manage costs.
*   **Rate Limiting:** The Genie API enforces a limit of **five questions per minute** when called from Microsoft Foundry. Design your user experience to discourage rapid, sequential querying.

> [!IMPORTANT]
> **Network and Security Requirements**
> *   **Preview Feature:** You must enable the **Managed MCP Servers** preview feature in your Azure Databricks workspace.
> *   **Connectivity:** Ensure network access is configured between Microsoft Foundry and your Databricks workspace, accounting for any IP restrictions or private endpoints.
> *   **Permissions:** Users configuring the connection in Foundry must have permissions to use the Genie space in Databricks.

### Cost and Limitations

*   **Cost Structure:** Costs include Microsoft Foundry charges for agent usage/API calls and Azure Databricks charges for serverless SQL compute used by Genie. Evaluate expected query volume to estimate total cost of ownership.
*   **Public Preview:** This feature is currently in Public Preview. While suitable for development and testing, it may undergo changes before general availability. Monitor Azure Databricks release notes for updates to configuration or functionality.
*   **Throughput:** For scenarios requiring higher throughput than the standard rate limit, contact your Databricks account team to discuss enterprise options.
