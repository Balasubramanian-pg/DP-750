## Apply Naming Conventions for Compute and Development Resources

Consistent naming extends beyond data objects to the operational infrastructure that processes them. When clusters, jobs, notebooks, and dashboards follow predictable patterns, teams can navigate the workspace efficiently, trace lineage without documentation, and enforce ownership boundaries at a glance.

### Compute Resources

Compute names should immediately communicate purpose, environment, and cost expectations. This transparency is critical for managing spend and applying appropriate access controls.

| Resource Type | Naming Pattern | Example | Purpose |
| :--- | :--- | :--- | :--- |
| **Clusters** | `{environment}_{domain}_cluster` | `dev_sales_cluster`, `prod_etl_cluster` | Distinguishes development experimentation from production workloads; signals cost sensitivity. |
| **Jobs** | `job_{layer}_{purpose}` | `job_bronze_orders_ingestion`, `job_gold_sales_aggregation` | Aligns with Medallion architecture; makes pipeline dependencies visible. |
| **Pipelines** | `pipe_{domain}_{purpose}` | `pipe_orders_processing`, `pipe_customer_cleaning` | Identifies Lakeflow Declarative Pipelines by domain and function. |
| **Streaming** | `stream_{source}_to_{target}` | `stream_kafka_to_bronze`, `stream_iot_sensor_data` | Makes data flow explicit without requiring external documentation. |

> [!NOTE]
> **Cost Visibility Through Naming**
> Including the environment prefix (e.g., `dev_`, `prod_`) in cluster names allows finance and platform teams to quickly identify non-production resources during cost reviews. A cluster named `ad_hoc_analysis_cluster` without an environment tag creates ambiguity about whether it should be running 24/7 or terminated after use.

### Development Artifacts

Notebooks and repositories should mirror your data architecture. When folder structures and file names align with job names and data layers, the entire workflow becomes self-documenting.

#### Notebook Organization

Adopt a folder hierarchy that reflects the Medallion architecture:

```text
/Repos/sales_project/
├── bronze/
│   └── ingestion_orders/
├── silver/
│   └── transformation_orders/
└── gold/
    └── sales_aggregation/
```

Individual notebooks should follow the pattern `notebook_{layer}_{purpose}`, such as `notebook_bronze_orders_ingestion` or `notebook_gold_sales_reporting`. This creates direct correspondence between notebook names and the jobs that execute them.

#### Repository Naming

Use `repo_{project_name}` (e.g., `repo_sales_project`, `repo_customer_analytics`) to map Databricks repositories to their Git remotes. This convention simplifies CI/CD configuration and ensures developers can locate the correct repository without guessing.

### Dashboards and Monitoring

Business-facing assets require names that prioritize discoverability over technical detail. Users should find what they need without understanding the underlying data pipeline.

| Asset Type | Naming Pattern | Example | Audience Benefit |
| :--- | :--- | :--- | :--- |
| **Dashboards** | `dashboard_{domain}_{purpose}` | `dashboard_sales_performance` | Business users locate relevant reports by domain and intent. |
| **SQL Queries** | `query_{purpose}` | `query_monthly_sales_report` | Teams identify reusable queries for similar reporting needs. |

> [!IMPORTANT]
> **Avoid Technical Jargon in User-Facing Names**
> Dashboard and query names serve business consumers, not engineers. `dashboard_sales_performance` is superior to `dashboard_gold_agg_v3_final`. Reserve technical layer indicators (`bronze`, `silver`, `gold`) for development artifacts; use business terminology for consumption-layer assets.

### Cross-Resource Consistency

The greatest value of naming conventions emerges when patterns align across resource types. When a job named `job_silver_orders_transformation` executes a notebook named `notebook_silver_orders_transformation` and produces a table in the `silver` schema, the entire lineage becomes traceable through naming alone. This consistency reduces onboarding time, simplifies debugging, and makes governance policies easier to apply and audit.
