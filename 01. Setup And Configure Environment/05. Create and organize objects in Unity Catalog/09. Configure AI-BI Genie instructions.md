# Configure AI/BI Genie Instructions

AI/BI Genie transforms how business users interact with data by allowing them to ask questions in natural language. However, an AI model is only as good as the context it receives. Without guidance, Genie may misinterpret technical column names, miss business-specific logic, or fail to join tables correctly. Configuring **Genie instructions** bridges this gap, turning raw Unity Catalog metadata into a rich knowledge store that empowers both humans and AI to understand your data accurately.

## 1. Build the Foundation: Selecting Tables

A Genie space is built on a curated subset of your data. The goal is not to expose everything, but to provide exactly what is needed to answer a specific set of business questions.

*   **Start Small:** Begin with 5–10 highly relevant tables. A focused scope reduces noise and improves Genie’s accuracy.
*   **Business-Centric Selection:** Choose tables that align with a specific domain (e.g., Sales, Logistics, Finance). For a sales space, include `opportunities`, `accounts`, and `products`, but exclude unrelated HR or IT assets.
*   **Expand Iteratively:** Add more tables only as user questions reveal gaps in the current dataset.

> [!NOTE]
> **Limit:** You can select up to 25 tables or views per Genie space.

## 2. Enhance Discoverability: Metadata Refinement

Unity Catalog provides the structural metadata, but Genie spaces allow you to layer **business context** on top of it without altering the underlying objects. This is done in the **Configure > Data** section.

### Table and Column Descriptions
Replace technical jargon with plain language.
*   **Technical:** `fcst_cat` stores forecast category codes.
*   **Business-Ready:** "Indicates whether an opportunity is in the Pipeline, Best Case, or Commit stage."

### Synonyms
Users rarely speak in database column names. Add synonyms to help Genie map natural language to your schema.
*   **Column:** `fcst_cat`
*   **Synonyms:** "forecast," "pipeline status," "category," "stage."

### Hiding Technical Columns
Surrogate keys, internal IDs, and audit timestamps often confuse both users and AI. Hide these columns to keep the interface clean and focus Genie on business-relevant data.

## 3. Define Relationships: Joins and Prompt Matching

Genie needs to know how tables connect and what values they contain to write accurate SQL.

### Join Relationships
While Genie can detect foreign keys from Unity Catalog, you should explicitly define joins for clarity and complex logic.
*   **Example:** Link `opportunity` to `accounts` via `opportunity.accountid = accounts.id`.
*   **Cardinality:** Specify if the relationship is One-to-One, One-to-Many, etc. This helps Genie avoid duplicate rows in aggregations.

### Prompt Matching
Prompt matching helps Genie understand the actual data values within your columns.
*   **Format Assistance:** Shows Genie representative examples of data formats (e.g., date styles, currency symbols).
*   **Entity Matching:** Curates a list of distinct values for categorical columns (e.g., State Codes like 'CA', 'NY'). When a user asks for "California," Genie knows to look for 'CA'.
    *   **Limit:** Up to 1,024 distinct values per column across 120 columns.
    *   **Refresh:** Regularly refresh prompt matching data to capture new values as your data evolves.

## 4. Teach Business Logic: SQL Instructions

Instructions are the most powerful tool for guiding Genie. They come in three forms:

### SQL Expressions
Define reusable business concepts like measures, filters, or dimensions.
*   **Measure:** `gross_margin` defined as `(revenue - cost) / revenue`.
*   **Dimension:** `fiscal_quarter` extracted from a date field.
*   **Benefit:** Genie uses these expressions automatically when users ask about "margin" or "quarterly performance."

### Example SQL Queries
Provide concrete examples of how to answer specific, complex questions.
*   **Question:** "What's our current pipeline by region?"
*   **SQL:**
    ```sql
    SELECT accounts.region AS Region, 
           SUM(opportunity.amount) AS Pipeline 
    FROM opportunity 
    JOIN accounts ON opportunity.accountid = accounts.id 
    WHERE opportunity.forecastcategory = 'Pipeline' 
      AND opportunity.stagename NOT LIKE '%closed%' 
    GROUP BY accounts.region;
    ```
*   **Trusted vs. Contextual:** If you use parameters (e.g., `:region`), Genie marks the query as **Trusted**, giving users high confidence. Non-parameterized examples serve as contextual guides.

### General Text Instructions
Use the **Text** tab for global rules that don’t fit into SQL.
*   **Example:** "Our fiscal year starts in February. Always convert timestamps to EST."
*   **Caution:** Use sparingly. Too many general instructions can dilute their impact.

## 5. Understand Limits and Governance

Genie spaces have two key limits to encourage quality over quantity:

| Limit Type | Cap | Includes | Excludes |
| :--- | :--- | :--- | :--- |
| **Instructions Limit** | 100 | Example SQL queries, SQL functions, General text block. | Column descriptions, prompt matching, table descriptions. |
| **Knowledge Store Snippets** | 200 | Table descriptions, Join relationships, SQL expressions. | Example SQL queries, general text, column descriptions. |

## 6. Iterate and Refine

Configuring Genie is not a one-time task. It requires continuous improvement based on real user interactions.

1.  **Test Early:** Ask common business questions yourself and review the generated SQL.
2.  **Add Instructions from Failures:** If Genie generates incorrect SQL, fix it manually and click **Add as instruction**. This teaches Genie the correct pattern for next time.
3.  **Leverage Knowledge Mining:** Genie automatically suggests new joins and SQL expressions based on approved queries. Review these suggestions to enrich your knowledge store.
4.  **Monitor Feedback:** Use the **Monitoring** tab to see which questions users rated as incorrect. Adjust metadata or instructions to address recurring issues.

By treating your Genie space as a living knowledge base, you ensure that business users get accurate, trustworthy answers while maintaining strict governance over your data assets.
