# Data governance using Unity Catalog and Microsoft Purview

## The Imperative for Unified Data Governance

Data governance is critical for ensuring that data within an organization is managed securely, efficiently, and in compliance with evolving regulations. In modern enterprises, data is rarely centralized; it is distributed across databases, data warehouses, data lakes, and multiple catalogs. It exists in diverse formats—ranging from Parquet and CSV to Delta Lake—and spans both structured tables and unstructured files. Beyond raw data, organizations must also govern complex assets such as machine learning models, notebooks, and dashboards. This fragmentation creates significant silos across sources, formats, and asset types.

These governance challenges directly impact the value organizations can derive from their data and AI investments:

*   **Increased Risk and Inefficiency:** Fragmented governance elevates compliance, security, and data quality risks. It also creates operational inefficiencies as teams struggle to maintain a consistent, reliable view of their data and AI environments.
*   **Vendor Lock-in and Higher Costs:** Limited connectivity restricts the ability to adopt new technologies as requirements change. Poor interoperability complicates collaboration and scaling, often leading to higher costs driven by the use of multiple disparate tools and the duplication of data across systems.
*   **Stifled Innovation:** A lack of built-in intelligence restricts the broader use of data and AI platforms, particularly for nontechnical users. This barrier slows down innovation, delays decision-making, and prevents organizations from fully realizing the potential of their data and AI investments.

> [!NOTE]
> **Azure Databricks**, when combined with **Unity Catalog** and **Microsoft Purview**, provides a robust solution for managing and governing these distributed assets effectively, bridging the gap between fragmented sources and unified organizational control.

## Unity Catalog

Unity Catalog provides a centralized framework for managing access, discovery, lineage, audit logs, and quality monitoring across all data and AI assets within Azure Databricks. Its policies apply consistently across every workspace in a given region, ensuring uniform governance regardless of where the work is performed.

### The Metastore
The metastore serves as the top-level metadata container, holding information about data assets and the permissions that govern them. Typically, an organization maintains one metastore per region, allowing multiple workspaces to share this central repository of metadata and security policies.

### Three-Level Namespace Hierarchy
Unity Catalog organizes data assets using a structured, three-level hierarchy:

`catalog.schema.table_or_other_object`

*   **Catalogs:** Group assets, typically aligned with specific teams, business units, or environments (e.g., Production, Development).
*   **Schemas (Databases):** Subdivisions within catalogs that organize assets more granularly, often by project or specific use case.
*   **Objects:** The individual assets residing within schemas, including tables (managed or external), views, volumes, functions, and machine learning models.

### Table Management
Tables within Unity Catalog can be configured as either managed or external:

*   **Managed Tables:** Unity Catalog handles both governance and storage. These tables are always stored in the Delta Lake format, ensuring transactional reliability and performance.
*   **External Tables:** Unity Catalog manages access control from within Databricks, but the underlying data lifecycle and storage remain managed externally. This supports a variety of formats, including Delta, CSV, JSON, and Parquet.

### Fine-Grained Access Control
Unity Catalog implements precise access control via ANSI SQL commands, extending from the metastore and catalog levels down to individual rows and columns.

> [!Tip]
> To grant the `finance-team` user group permission to create new tables within the `myschema` schema of the `mycatalog` catalog, you would use the following command:
>
> ```sql
> GRANT CREATE TABLE ON SCHEMA mycatalog.myschema TO `finance-team`;
> ```

### Discovery and Lineage
Exploring data assets is streamlined through the **Catalog Explorer** and a robust search interface. To aid discovery, assets can be enriched with tags, comments, and AI-generated descriptions. Once an asset is identified, users can leverage features such as:

*   **Data Lineage:** A complete visual history of how data moves and transforms.
*   **Table Insights:** Automated statistics and quality metrics.
*   **Entity Relationship Diagrams:** Visual representations of how tables connect.

Unity Catalog provides a comprehensive audit trail, logging access and tracking lineage down to the column level.

> [!NOTE]
> In most accounts, Unity Catalog is enabled by default when a workspace is created. You can begin using it immediately with default settings, though optional configurations are available for more advanced governance requirements.
