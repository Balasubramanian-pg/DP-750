## Serverless Compute

Serverless compute represents a shift from infrastructure management to workload execution. Managed entirely by Azure Databricks, it abstracts away the complexities of provisioning, configuring, and scaling resources. These workloads run within the Databricks-managed Azure subscription, meaning no virtual machines or networking components appear in your own subscription.

### Core Characteristics

*   **Instant Availability:** Startup times typically range from 2–6 seconds, eliminating the wait associated with classic cluster provisioning.
*   **Dynamic Scaling:** The platform automatically scales up to handle increased query volume and scales down during idle periods, ensuring you only pay for active processing time.
*   **Versionless Runtime:** Azure Databricks automatically applies upgrades and security patches, ensuring you always have access to the latest features without manual migration effort.
*   **Unity Catalog Requirement:** Serverless compute is tightly integrated with Unity Catalog for centralized governance and metadata management.

### Supported Workloads

Serverless compute is available for a wide range of data engineering and analytics tasks:

| Workload Type | Description |
| :--- | :--- |
| **Notebooks** | Interactive Python and SQL development with automatic resource allocation. |
| **Jobs** | Automated workflows that execute without any infrastructure setup or management. |
| **Pipelines** | Lakeflow Spark Declarative Pipelines (SDP) that scale on-demand for reliable data ingestion and transformation. |
| **SQL Warehouses** | Optimized SQL query execution featuring Intelligent Workload Management for high-concurrency BI. |

### Limitations and Constraints

While serverless offers significant operational benefits, it operates within a managed environment that restricts certain low-level customizations. It is **not** suitable for workloads requiring:

*   **Languages:** Scala or R notebooks are not supported.
*   **APIs:** RDD (Resilient Distributed Dataset) APIs are unavailable.
*   **Libraries:** JAR libraries are generally restricted (though JAR tasks in Lakeflow Jobs are currently in Public Preview).
*   **Configuration:** Custom Spark configurations and full control over the runtime environment are not permitted.

> [!IMPORTANT]
> If your workload relies on Scala, R, RDD APIs, or requires specific Spark configuration tuning, you must use **Classic Compute** with dedicated access mode. For most modern Python and SQL-based workflows, however, serverless provides the fastest, most cost-effective path to production.
