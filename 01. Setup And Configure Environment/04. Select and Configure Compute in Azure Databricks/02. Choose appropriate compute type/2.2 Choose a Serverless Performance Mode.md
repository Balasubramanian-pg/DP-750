## Choose a Serverless Performance Mode

For serverless jobs and pipelines, Azure Databricks offers two performance modes that allow you to balance startup latency against cost efficiency. Selecting the right mode ensures your workloads are both responsive and economically optimized.

### Performance Modes Comparison

| Feature | Performance-Optimized (Default) | Standard |
| :--- | :--- | :--- |
| **Startup Time** | Seconds (uses warm resource pools). | 4–6 minutes. |
| **Cost Efficiency** | Standard DBU rates. | Up to **70% lower** DBU consumption. |
| **Best For** | Interactive workloads, latency-sensitive jobs, and urgent data processing. | Scheduled batch jobs, overnight ETL, and pipelines where startup delay is acceptable. |
| **Availability** | All serverless workloads (Jobs, Pipelines, Notebooks). | Jobs and non-continuous Pipelines only. |

### Configuration and Constraints

*   **Default Behavior:** Performance-optimized mode is the default setting to ensure the fastest possible execution for most users.
*   **How to Switch:** You can enable Standard mode by toggling the **Performance optimized** setting in the job details page.
*   **Limitations:**
    *   **Notebooks:** Only support performance-optimized mode to maintain a responsive interactive experience.
    *   **Continuous Pipelines:** Cannot use Standard mode due to the need for immediate availability.
    *   **API Submissions:** One-time runs submitted via the `runs/submit` API endpoint do not support Standard mode.

> [!TIP]
> **Cost Optimization Strategy**
> For non-urgent, scheduled batch processes—such as nightly data aggregation or weekly reporting—switching to **Standard mode** can yield significant cost savings without impacting business outcomes. Reserve performance-optimized mode for workflows where every second of latency matters.
