## SQL Warehouses

SQL warehouses are specialized compute resources designed exclusively for SQL queries, analytics, and business intelligence. Unlike all-purpose clusters, they are optimized for high-concurrency SQL execution, leveraging technologies like **Photon** and **Predictive IO** to accelerate query performance.

### Types of SQL Warehouses

Azure Databricks offers three distinct types of SQL warehouses, each tailored to different performance and networking requirements.

| Feature | Serverless SQL Warehouse | Pro SQL Warehouse | Classic SQL Warehouse |
| :--- | :--- | :--- | :--- |
| **Performance** | Optimal; uses Intelligent Workload Management (IWM). | High; supports Photon and Predictive IO. | Entry-level; supports Photon only. |
| **Startup Time** | 2–6 seconds. | ~4 minutes. | ~4 minutes. |
| **Scaling** | Dynamic, predictive scaling based on demand. | Basic autoscaling; less dynamic than serverless. | Basic autoscaling. |
| **Networking** | Databricks-managed subscription (no custom VNet). | Supports custom VNets and private links. | Supports custom VNets and private links. |
| **Best For** | Most BI dashboards, ETL jobs, and ad-hoc analysis. | Workloads requiring custom networking or on-premises federation. | Basic exploration when other options are unavailable. |

### Key Technologies

*   **Photon:** A native vectorized engine that significantly accelerates SQL query execution across all warehouse types.
*   **Predictive IO:** Optimizes data retrieval by anticipating which data blocks will be needed next, reducing latency.
*   **Intelligent Workload Management (IWM):** Exclusive to **Serverless** warehouses, IWM predicts resource needs and dynamically scales clusters to maintain consistent performance during peak demand.

### Strategic Selection

*   **Choose Serverless for Speed and Simplicity:** For the majority of SQL workloads, serverless warehouses provide the fastest startup, lowest operational overhead, and most efficient cost model through dynamic scaling.
*   **Choose Pro for Network Integration:** When your SQL queries need to access data in on-premises databases via federation or interact with services within your private virtual network, Pro warehouses are the required choice.
*   **Choose Classic for Legacy or Basic Needs:** Reserve classic warehouses for scenarios where serverless and pro options are not available, or for very basic interactive exploration where advanced performance features are not critical.

> [!NOTE]
> While all SQL warehouse types are optimized for SQL execution, **Serverless SQL Warehouses** represent the modern standard for analytics in Azure Databricks, offering a responsive, managed experience that eliminates the need for manual infrastructure tuning.
