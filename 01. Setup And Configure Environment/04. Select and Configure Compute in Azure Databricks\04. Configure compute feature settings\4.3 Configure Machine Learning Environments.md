## Configure Machine Learning Environments

Machine learning workloads demand a distinct computational environment compared to standard data engineering tasks. They require specialized runtimes, specific hardware accelerators, and configurations that prioritize model training efficiency over distributed data shuffling.

### Databricks Runtime ML

The foundation of any ML workload in Azure Databricks is the **Databricks Runtime ML**. Unlike the standard runtime, this version comes pre-installed with a comprehensive suite of popular machine learning libraries, including TensorFlow, PyTorch, scikit-learn, and XGBoost.

> [!TIP]
> **Reduce Setup Friction**
> By selecting a Databricks Runtime ML version, you eliminate the time-consuming process of manually installing and resolving dependencies for complex ML frameworks. This ensures immediate compatibility between packages and allows data scientists to begin experimentation the moment the cluster starts.

### Hardware Configuration: CPU vs. GPU

The choice of hardware depends heavily on the complexity of the models being trained.

*   **Single-Node CPU for Experimentation:** For initial model prototyping and testing with smaller datasets, a single-node compute resource with a large instance type is often sufficient. This configuration minimizes the overhead of distributed shuffle operations while providing ample memory and CPU power for local processing.
*   **GPU Acceleration for Deep Learning:** For computationally intensive tasks such as image recognition, natural language processing (NLP), and neural network training, GPU-enabled instances are essential. These instances leverage parallel processing to accelerate matrix operations, reducing training times from hours to minutes.

> [!WARNING]
> **Photon Incompatibility**
> When using GPU-enabled instances, you **must disable Photon acceleration**. The Photon engine is optimized for CPU-based vectorized execution and is not compatible with the GPU drivers and CUDA frameworks required for deep learning workloads. Attempting to use both will result in configuration errors.

### Strategic Environment Setup

1.  **Start Small:** Begin with a single-node CPU cluster for data cleaning and baseline model training.
2.  **Scale Up with GPUs:** Transition to multi-node GPU clusters only when moving to deep learning models or when dataset sizes make CPU training impractical.
3.  **Verify Dependencies:** Even with Runtime ML, always verify that specific library versions match your code requirements, especially when migrating models from local development environments.

> [!NOTE]
> Properly configured ML environments not only speed up model training but also ensure reproducibility. By standardizing on Databricks Runtime ML and appropriate hardware profiles, teams can share notebooks and experiments with confidence that the underlying infrastructure supports their computational needs.
